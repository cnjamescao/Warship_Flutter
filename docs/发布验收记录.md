### 3.2 F-22 基准操作员程序（协议 §5.1 / 测试计划第 95 行）

**裁决**：不要求产品本人试玩；由**指定的研发或 QA 在 release 构建中
真实操作**录制无伤通关基准；**禁止脚本搜索、作弊或手工编辑回放**；
连续 10 次合规实操仍不能完成时，**按数值/可通关性缺陷处理**
（而不是降低成功条件）。

**好消息**：采集所需的格式**已经具备** —— `ReplayFrame` 已支持
`cardSelection`（选卡）与 `riskSelection`（风险门选项），
`ReplayRecorder` 已在用；**不需要为录制新增数据结构**。

**操作员步骤**：
1. 用 `flutter build macos --release`（或目标平台 release）构建；
   **不得用 debug 构建**、不得开作弊、不得改数值；
2. 以 `seed=0x4E454F4E0001` 开局，正常操作通关。
   **成功条件：180 秒前胜利 且 全程 `hpDamage=0`（护盾承伤允许）**；
3. **保留录屏证据**；
4. 产出 `test/fixtures/replays/baseline_clear_v1.json`，含 `seed`、
   `contentVersion=2.0.5-release`、正式 `素材/manifest.json` 的 SHA-256、
   逐帧 `InputFrame`、选卡 ID、风险门选项、期望的 `RunEnded` 摘要；
5. 由**技术负责人审核后冻结**并纳入版本控制；
6. 冻结后**每次构建连续回放 3 次**：均胜利、HP 从未受伤、
   事件摘要 hash 一致。

**⚠️ 诚实的进度说明（2026-10-15）**：录制机制**已完成** ——
`lib/game/core/baseline_recorder.dart` 在 `WarshipV2Game` 的**唯一推进点**
挂钩，忠实记录逐帧输入与真实选择，并带**一票否决**（掉过一次 HP 即不合格）。
`flutter build macos --release` 已验证可构建（64.1 MB）。

**但"真实人工操作"这一步我无法代替**：
协议要求「基准首次录制**必须来自一次真实人工操作**」，且
**禁止用脚本搜索或假回放替代**。我无法操作键鼠、也无法观察运行中的画面，
而任何自动化的玩法（脚本/AI 试玩）**正是协议明文禁止的**。
因此这一步**必须由能实际操作的人完成** —— 即使角色已指定。

### 操作员的确切命令（已实测可构建）

```bash
# 1) 带录制开关构建 release（把 <输出路径> 换成你想要的绝对路径）
flutter build macos --release \
  --dart-define=WARSHIP_RECORD_BASELINE=$HOME/Desktop/warship_baseline.json

# 2) 启动并真实通关
open build/macos/Build/Products/Release/warship_flutter.app
#    以 seed=0x4E454F4E0001 开局；成功条件 = 180 秒前胜利 且 全程无 HP 伤害

# 3) 通关后若合规，录制器会打印已写出的路径；再盖章为正式基准
dart run tool/finalize_baseline.dart $HOME/Desktop/warship_baseline.json
```

**录制默认关闭** —— 不加 `--dart-define` 的构建不会产生任何基准文件，
也不会因为录制逻辑影响正常游玩。

**验收到的行为**：
* 带开关的 release 构建成功（64.2 MB），路径值确实编入
  `App.framework/Versions/A/App`；
* **只有**满足成功条件才写出文件；不合格时打印原因且**什么都不写**
  （不允许把"最接近的一次"留下当基准）；
* `finalize_baseline.dart` 会**拒绝**：非胜利 / 掉过 HP / 版本不符 /
  **帧数与时长相不自洽**（防手工删改），然后才盖上正式
  `素材/manifest.json` 的 SHA-256。
