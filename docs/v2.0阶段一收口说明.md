## 七、研发的处理原则（本阶段一贯遵守）

1. **不擅自增删功能**。文档未定义处先查文档；查不到就**问你**，不自己拍板。
2. **不擅自改内容**（素材、数值、文案）。发现缺口就**登记 + 冻结**，
   而不是顺手改掉。
3. **不把未验证的写成已验证**。本阶段每一份报告都区分「已覆盖 / 未覆盖」，
   并主动记录自己的失误（含 5 次"没验证就下结论"、2 次臆造断言、
   1 次引入 `Concurrent modification` 崩溃、1 次漏跑 golden）。
4. **测试要制造能让缺陷暴露的条件**，而不是只走顺利路径
   —— 本阶段据此抓出了多个只测"成功路径"发现不了的问题。
5. **对着规范原文逐句核对，而不是看自己的测试名**
   —— 这一条在本阶段找出了 **11 处**被我（或历史）缩水的验收点，
   其中没有一处是代码缺陷，**全是覆盖面被悄悄缩小**。

## C. 本阶段自行发现并修复的缺陷（11 项）

**阻断性**：

1. **F-17 项目无法编译为 Web** —— PCG32 用 64 位字面量，`dart2js` 编译期报错。
   直接违背目标里「为 Web 阶段预留扩展性、**避免二次重写**」。
2. **F-18 PRNG 并非其自报的 `pcg32-xsh-rr`** —— XSH-RR 要求逻辑右移，
   而 Dart 对负数的 `>>` 是算术右移。用 Python 权威参照逐值对照确认。
   （修复同时解决 F-17：改用 `fixnum` 的 `Int64`。）

**真实缺陷**：

3. `_onBossDefeated` 没清在飞的敌方投射物 → **胜利后玩家仍在挨打**（F-20 部分）
4. `DegradationLevel.allows` 用 `index <= requested.index` → **最后一档永不关闭**
5. `AudioService` 用合并静音 → **关掉一个开关不生效**
6. `EnemySystem` 只在入场帧初始化 `attackCooldown` → 部分敌人**永不攻击**
7. `_BriefingScreenState` 用不可取消的 `Future.delayed` → **真实计时器泄漏**
8. **精英词缀完全未接线** —— 精英有 6 倍血但没有任何词缀（"声明了没接上"）
9. 简报界面**缺三行提示** —— `briefing.tip.*` 的 key 存在但没渲染（同类）

**我自己的失误**（主动记录）：

10. 修 F-20 时第一版直接在被遍历时改 `projectiles` → 抛
    `Concurrent modification during iteration`（被测试当场抓出）
11. **F-23 改了 PRNG 却没重跑 golden** → `draft.png` 基线静默失效
