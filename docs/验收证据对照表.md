## 逐项说明

### AC-01 100 个固定 seed 回放 — 🔶
「同输入下升级候选、风险门、精英词缀、得分和胜负完全一致」

- **已做**：100 个 seed 各跑 1200 帧（20 秒有效战斗，覆盖 15.0 秒的首个升级草案）。其中 12 个 seed **双跑比对**，断言事件摘要、得分、升级候选顺序、风险门可选项完全一致。
- **未做**：另外 88 个 seed 只跑一次（双跑全部 100 个会让测试时间翻倍）。精英词缀在 65 秒后出现，超出 20 秒窗口，**未被本用例覆盖**——需由更长的固定回放（AC-06 基准）补充。
- **注意**：事件摘要**刻意不含负载**（浮点坐标跨平台可能有极小差异），因此它验证事件**结构**确定性；数值一致性由 score 与候选列表比对保证。

### AC-02 横向分辨率 — 🔶
「16:9、4:3、21:9 和带安全区设备均不拉伸逻辑世界，HUD 不越界」

- **已做**：`CameraComponent.withFixedResolution(1920×1080)` 保证逻辑世界不与屏幕分辨率耦合；`ViewportMath` 提供屏幕↔逻辑换算并使 **letterbox 不吞输入**；widget 测试覆盖常规 resize、极小窗口（1×1）、极端长宽比。
- **未做**：**三种目标宽高比的真实截屏比对**（16:9 / 4:3 / 21:9）与 Golden 基线。

### AC-03 5 分钟生命周期循环 — ✅
「开始、暂停、失焦、升级、风险门、死亡、重开 20 次后无残留实体、持续音或重复输入」

- **已做**：`test/game/acceptance_lifecycle_test.dart` 跑满 20 轮。每轮都先断言新局是干净的（出生点、计数归零、无实体、无未消费事件），再走完「推进 3 秒 → 暂停 → 恢复 → 失焦 → 再推进制造投射物与危险区 → 死亡」全部路径，释放后逐项检查残留：敌人 / 投射物 / 危险区 / 未消费事件 / 待选草案 / 风险门 / Boss / 持续音句柄。
- **另断言**：循环结束后新开一局，实体序号从 1 重新开始（分配器未跨局累积）；重开不继承上一局的移动输入（防"粘键"）。
- **说明**：本用例覆盖的是**逻辑与音频句柄**层面的残留。Flutter Widget / Flame 组件的监听器残留由 `test/widget_test.dart` 与 `test/widget/hud_test.dart` 的既有回归覆盖。

### AC-04 公平性 — 🔶
「每种攻击在命中前有对应预警；生成点满足 360 px 安全距离；无不可躲避 Boss 循环」

- **已做**：生成点强制 ≥360 px 且无合法点时延后（超过 1.0 s 才退化为最远点，绝不贴脸）；敌方与 Boss 攻击的预警时序逐一断言；Boss 六招几何与时长。
- **未做**：**「无不可躲避 Boss 循环」的可判定化**。目前只验证了单招参数，没有做"招式序列 × 玩家可行走位"的可解性分析。

### AC-05 状态视觉（13 个） — 🔶
「产品设计文档 7.5 的全部 13 个状态均有正确视觉、音频和结束条件」

- **已做**：`AssetBindingTable` 覆盖真实 manifest 的**全部 368 条图形绑定与音频绑定**，逐条验证「事件 + when → Asset ID + renderState」精确解析；多状态资源的每个声明状态都有可达路径；`transientMs` 与 `restoreFromSnapshot` 语义被校验。
- **未做**：这份证据证明的是**路由正确**，而不是**画面正确**。缺少 13 个状态的截图/Golden 逐项比对。

### AC-06 数值（无伤 180 s 前击败 Boss） — ⬜
「用无伤基准输入可在 180 秒前击败 Boss；新手基准输入能稳定达到 60 秒；站桩输入不能通关」

- **已做**：回放格式、录制/重放基础设施与确定性保证（`T-CORE-04` 通过）。已生成 `test/fixtures/replays/baseline_determinism_v1.json`。
- **未做**：**这三条基准输入本身**。该文件当前记录的是 6000 帧固定输入下的实际结果（`result: "running"`，未通关）。
- **阻塞原因**：无法凭空写出必然通关的输入序列。前置条件是先确认**玩法可通关**，而这需要人工试玩——研发侧从未实际游玩过 v2.0。

### AC-07 性能 — 🔶
「达到 §2 对象上限时仍满足帧时间目标；降级不影响预警、HUD、碰撞与输入」

- **已做**：帧时间滑动窗口采样与 p50/p95/p99 输出按 §2 预算（95% ≤20 ms、99% ≤33 ms）判定；降级顺序与门禁有测试；对象预算常量与 §6 一致；特效池受"预算 + 档位"双重限制。
- **未做**：**真实设备上的 p95/p99 实测数据**。以上全部是逻辑层验证，没有 profile/release 构建的采样结果。

### AC-08 离线 / Web — ⬜
「断网可完整开始、游玩、结算；首次用户手势后音频可用；隐藏页面自动暂停」

- **已做**：`AppLifecycleState.hidden`（浏览器 `visibilitychange(hidden)` 的映射）与 inactive/paused 走同一分支；本地存档用 `shared_preferences`（含 Web 实现）而非 `dart:io`。
- **未做**：**真实浏览器矩阵**（Chrome / Safari / Edge）、**离线验证**、**首次手势前音频被浏览器策略拦截后的恢复**。无任何 Web 端实测。

### AC-09 素材 — ✅
「每个运行时 Asset ID 有文件、元数据、许可证与回退策略；不存在未登记第三方资源」

- **已做**：193 条记录逐条验证运行时文件存在、许可证非空、回退 ID 可解析；三条统一回退资源存在；许可证字段不含占位文本。
- **保留**：许可证的**法律层面**复核仍需人工（自动化只能拦住空值与明显占位）。素材侧另有四道发布门禁脚本（`素材/元数据/validate_*.py`），CI 每次运行。

## 距离发布验收还差什么

1. **人工试玩**：确认玩法可通关 —— 这是 AC-06 与后续一切数值验收的前置。
2. **Golden 基线**：HUD / 升级草案 / 风险门 / 暂停 / 结算五个界面。
3. **真实设备与浏览器实测**：AC-07 与 AC-08 的逻辑层准备已完成，缺实测数据。
4. **Golden 基线的平台问题**：CI 运行在 ubuntu，而基线若在 macOS 生成，
   字体渲染差异会让 golden 断言必然失败（规范本身也写明 Golden 只在
   "稳定平台"才必须）。需要先决定基线在哪一类平台上生成与比对 ——
   例如统一在 CI 的 ubuntu 上生成基线，或把 Golden 拆成独立的工作流。
