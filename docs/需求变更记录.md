## RC-01　F-12 色弱编码：必须使用正式 PNG，禁止几何等价替代

**确认时间**：2026-10-15（产品裁决）

| | 内容 |
| --- | --- |
| **变更前** | 「所有关键状态默认提供**颜色之外的第二识别维度**」——未限定实现载体，允许程序化几何图形 |
| **变更后** | 「**必须实际合成正式 PNG 素材，禁止用 Canvas 或程序化几何等价替代**」；叠层**始终显示**，不依赖任何设置开关 |
| **影响范围** | 危险/濒危、奖励/补给、稀有度、精英词缀、**预警**五类叠层；`UI-COLORBLIND-PATTERN-DANGER` / `-REWARD` / `-RARITY` 三张素材 |
| **测试影响** | 需断言"素材**被实际绘制**"（而非仅存在几何形状）；已新增绘制记录覆盖度守卫 |
| **研发落地** | 危险/低血、奖励、稀有度、词缀均已改为贴正式 PNG；F-37 进一步明确**世界空间**与**屏幕空间**的边界（见 RC-05） |

## RC-02　HUD 锚定口径：HUD 贴窗口边，不随世界留黑边

**确认时间**：2026-10-15（产品裁决：「**无论窗口大小，HUD 都应该在顶部**」）

| | 内容 |
| --- | --- |
| **变更前** | HUD 定位使用**逻辑世界坐标**（含保边偏移），非 16:9 窗口下 HUD 随世界一起下移 |
| **变更后** | HUD **锚定窗口边缘**（顶部/底部/左右均用"距窗口边的固定边距"），**与窗口尺寸无关**；战场仍保边（不拉伸逻辑世界，AC-02 仍然成立） |
| **影响范围** | `kHudSafeArea` 的语义；AC-02 的验收口径需明确"**HUD 贴窗口、战场保边**"两条并存 |
| **测试影响** | 新增静态守卫禁止 `bottom/right: viewportSize - logical×scale` 的反向锚定；新增 4:3 / 21:9 像素级基线 |
| **备注** | 此变更**明确了 AC-02 的判定边界**：以前"HUD 不越界"的断言无法区分上述两种口径 |

## RC-04　F-03 结算奖牌算法：不产生 `none`

**确认时间**：2026-10-16（产品正式追认）

| | 内容 |
| --- | --- |
| **变更前** | 技术协议 §3.2 写「胜利 gold；失败且曾进入 Boss P3 silver；失败且存活 ≥120 秒 bronze；**其余为 `none`**」——与产品基线 §8 冲突 |
| **变更后** | **正式规则**：**Gold** = 胜利；**Silver** = 失败且 Boss 剩余 HP < 35%；**Bronze** = 其他失败；**不产生 `none`** |
| **影响范围** | `UI-RESULT-MEDAL` 的档位来源；此前 `none` 状态不可达（F-02）随之消解 |
| **测试影响** | 奖牌档位用例需覆盖"任何失败都至少为 Bronze"；**不得**再断言存在 `none` |
| **研发落地** | 负责人已确认**实际代码已符合新规则，无需改代码** |

## RC-06　F-36 / F-38 新增「预警时序合同」

**确认时间**：2026-10-16（产品批复 F-36；随后批复 F-38 按同构实施）

这是本轮**最实质的新增需求**——此前只有零散的预警素材绑定，没有成体系的时序与渲染合同。

| # | 新增要求 |
| --- | --- |
| 1 | `telegraphSeconds > 0` 的攻击：**t=0 只发 `*Telegraphed`**，并以当时的 `origin`/`aimTarget`/`shape` 建立**不可变待执行攻击**；**到期同一步**才发 `*Fired` 并生成伤害实体 |
| 2 | 预警期间源实体被移除、风险门开启、胜利锁定、重开或非 Playing 状态，**待执行攻击必须取消/冻结且不得残留**（暂停 = 冻结：逻辑时钟不前进） |
| 3 | 渲染快照以**独立不可变 `TelegraphView`** 公开预警；**禁止**折叠进 `EntityView`；**禁止**表现层猜测目标 |
| 4 | 预警与危险区均处于**背景之上、实体之下**；**只允许 manifest 绑定的正式素材**，**不得用 Canvas 几何替代资源** |
| 5 | **几何与素材由 Domain 在 t=0 一并锁定**（不得由表现层按 `attackId` 猜 manifest 绑定——`sniper_line` 同时绑定机体与预警素材，猜绑定会把机体贴图当预警线拉伸旋转） |
| 6 | `sniper_line`：origin/aimTarget 在 t=0 锁定，线形预警**沿射线裁切到逻辑世界边界** |
| 7 | `bomber_drop`：落点固定为 t=0 的 origin；0.40 s 后创建**半径 90** 的 ACTIVE 危险区，持续 **2.2 s**、每 **0.25 s** 每目标至多 **8 点**伤害；**`warningSeconds` 为 0**（预警已由 TelegraphView 负责，不得重复预警） |
| 8 | **F-07 强制预警集合**明确为六招：`sniper_line`、`bomber_drop`、`boss_fan`、`boss_charge`、`boss_ring`、`boss_laser`；每招的 `*Telegraphed` 必须**先于伤害** |
| 9 | **Boss 四招同样适用**上述全部要求（F-38 按 F-36 同构实施） |

**影响范围**：技术协议 §3.2；测试计划新增"预警时序"与"取消/暂停回归"两类用例。

**研发落地**：F-36 六步 + F-38 全部完成；AC-04 六招逐项回归通过；新增 4 条 Boss Golden。

## RC-07　产品时长语义明确：150 / 180 / 190 秒

**确认时间**：2026-10-16（复核过程引用产品基线）

| 时点 | 语义 |
| --- | --- |
| **150 秒** | **Boss 必须已入场**（合同测试的正向断言） |
| **180 秒** | 未击败则进入狂暴（**唯一**变化：激光扫射时长改为 2.2 秒） |
| **190 秒** | **判负上限**；玩家存活且未胜利时，`combatSeconds < 190.0` 的每一步**不得**进入 Result |

**影响范围**：`V2AppFlow` 的流程合同；简报目标文案（「坚持 **190** 秒」——此前误用 3 秒展示倒计时，见 RC-08）。

**测试影响**：新增 `acceptance_v2appflow_contract_test.dart`（Boss 150 秒入场 + 190 秒前不提前 Result）。

## RC-08　F-25-02 / F-25-03 文案口径

**确认时间**：2026-10-16（产品批复）

| 条目 | 变更 |
| --- | --- |
| **简报目标** | 「坚持 {seconds} 秒，击败守门者 Aegis」中的 `seconds` 必须是**战斗时长上限 190**，**不是**简报界面的 3→1 展示倒计时。新增命名常量 `kRunObjectiveSeconds = 190` 并注明来源 |
| **暂停按钮语义标签** | 运行中按钮表示**动作**、暂停覆盖层标题表示**状态**，二者不得混用。**新增玩家可见文案 key `hud.pauseAria` =「暂停」**（原 key `pause.title` =「已暂停」仅用于覆盖层标题） |

**⚠️ 需产品/文案侧确认**：`hud.pauseAria` 是**新增的玩家可见文案**，研发按其语义择词为「暂停」。**若文案侧已有既定措辞，请指正**。
