| 项目 | 结论 |
| --- | --- |
| 审计日期 | 2026-10-16 |
| 审计范围 | 正式 manifest 的 127 个图形/UI、67 个物理音频、两套应用侧运行时副本 |

## 1. 审计方法与判定标准

本审计不是“文件存在检查”。对每个 manifest 图形状态执行文件存在、PNG/RGBA 可解码、
SHA-256 重复分组、状态名与语义交叉检查，并人工抽查角色、敌机、武器、HUD 和 UI 正常态。
音频同步检查 WAV/MP3、Cue、哈希及混音。

以下任一情况均为**占位/不合格素材**：

1. 两个不同玩法语义的正常态使用同一张图，例如武器、敌弹、预警和升级卡图标共用。
2. 角色/武器/预警的必要状态使用 UI 图标、回退剪影或纯空白替代。
3. 方向、风险、稀有度、生命/护盾/经验等玩家必须辨识的信息使用同一张正常态图。
4. 文件能被加载但与产品清单要求的对象、颜色、形状或状态含义不符。

仅当状态本身明确为不可见结束帧或禁用空态，且被逐项白名单说明时，二进制相同才允许保留。
当前包**没有**这样的版本化白名单，不能自动把 `disabled`、`pressed` 或 `end` 的重复视为合格。

## 4. 状态帧专项风险

- 大量 `disabled`、`pressed`、`focus`、`end` 状态彼此完全相同；其中部分可能是合理的
  “不显示”结束帧，但目前没有可供实现与 QA 使用的白名单，全部暂按待核验处理。
- `GFX-PLAYER-HIT-FLASH__end`、旧 `GFX-PLAYER-SHIELD-HIT__end` 等结束状态曾与无关 UI
  资源共用。本次已替换护盾受击 active/end；HP 受击层仍需通过正确的叠加混合而不是不透明覆盖呈现。
- 敌机、音频的独立性已通过；上述问题不应被错误归因到敌机资源。

## 5. 对一线研发的执行边界

1. 立即接入现有 `2.0.6-material-repair` manifest 中已更新的玩家护盾受击资源；v2.0.7
   仅为本审计/素材补丁编号，禁止修改客户端的运行时版本常量。
2. `GFX-PLAYER-SHIELD-HIT` 与 `GFX-PLAYER-HIT-FLASH` 都是 **effect overlay**：必须绘制在
   `GFX-PLAYER-BASE` 之上，使用 Screen/Additive（或等价仅提亮）混合和素材 alpha；不得以
   不透明普通混合覆盖机体，不得以全尺寸色块遮挡机体。
3. 护盾命中只播放 `GFX-PLAYER-SHIELD-HIT.active` 80–120 ms，然后淡入 `end` 并移除；
   HP 伤害才播放 `GFX-PLAYER-HIT-FLASH.active`。两者不能被“资源加载失败回退图”代替。
4. P0/P1 未完成资源不得由研发自行画临时图、换成 emoji、圆点或已有 Asset ID；保持 manifest
   路由，等待下一批素材包后仅做同步与状态映射接入。
5. 回归测试必须验证：护盾命中截图中玩家机体中心仍可见；HP 受击和护盾受击请求不同
   Asset ID；七向受击、风险门、三种拾取物和三种精英词缀在后续素材到位后各自请求独立资源。

## 6. 结论

v2.0.7 已消除“护盾命中是占位图”的直接问题，并保留敌机/音频修复成果；但正式素材包仍有
大量跨语义图形占位。因此**不得进入视觉发布验收**，F-27 保持 P0 阻塞，直至第 3 节所有
P0 项重制且第 4 节有白名单和自动门禁。
