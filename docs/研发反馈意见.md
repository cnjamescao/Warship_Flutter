### FV21-01　多个 Asset ID 共用同一张 sheet，与构建脚本 basename 唯一性冲突

**级别**：**P0（阻塞 B0）**
**状态**：**待确认**
**发现时间**：2026-10-17（B0 §2.2 写入 manifest 时）

#### 现象

素材规范 §2 的表格中，**多组 Asset ID 指向同一个物理文件**：

| sheet 文件 | 引用它的 Asset ID 数 |
| --- | ---: |
| `图形/武器形态/GFX-V21-WEAPON-STYLES-SHEET.png` | **5**（`GFX-V21-WPN-PRISM/ARC/PLASMA/NEEDLE/MISSILE`） |
| `图形/武器形态/GFX-V21-WEAPON-IMPACTS-SHEET.png` | **5**（`…-IMPACT` 五条） |
| `图形/动效序列/UI-V21-NONBLOCKING-NOTICE-SHEET.png` | **3**（`UI-V21-UPGRADE-NOTICE` / `-SECTOR-CLEAR-NOTICE` / `-NOTICE-SPARK`） |
| `图形/奖章/UI-V21-RESULT-MEDALS-SHEET.png` | **3**（`GOLD` / `SILVER` / `BRONZE`） |

每个 ID 通过各自的 **`frameRect`** 从同一张 sheet 裁出自己那一格 ——
这正是规范 §2 与 §4.2 描述的模型（"加载完整 sheet 后严格以 frameRect 生成 sprite"）。

但**构建脚本强制 basename 唯一**：

```
tool/build_v2_assets.dart:56-62
  final owner = seen[basename];
  if (owner != null) {
    failures.add('basename 冲突：$basename 同时属于 $owner 与 ${raw['assetId']}');
```
（注释写明"basename 唯一性是扁平化的前提 —— 不满足就必须失败，不能静默覆盖"）

**⇒ 按规范写入 manifest 后，`tool/build_v2_assets.dart` 必然失败**，B0 无法完成。

#### 依据

* `Spec/03_素材/v2.1/02_素材清单与制作规范.md` §2 表格（多 ID 同文件 + 各自 `frameRect`）、§4.2；
* `tool/build_v2_assets.dart` 的 basename 唯一性检查。

**已核查**：`Spec/02_技术/v2.1/` 与 `Spec/03_素材/v2.1/` 全文**均未涉及**
"多 ID 共用 sheet"或"basename 唯一性如何放宽"。
（`01_素材生产验收与工作边界.md` §差异审查提到"不同游戏语义不能共用同一画面"，
但那是指**画面内容**不得雷同，与本条"同一张 sheet 的不同格子分属不同 ID"不是同一件事。）

#### 影响

* **阻塞 B0 退出门禁**（料 hash 检查 / manifest 生成无法通过）；
* 直接决定 manifest schema 与构建流水线的设计（属蓝图 B0 的
  「**Asset manifest schema 评审通过**」范围）。

#### 体积影响（实测，供裁决参考）

```
方案 A（sheet 共享一份）        ≈  5.9 MB
方案 B（每 ID 一份副本）       额外 ≈ 70.6 MB   ← 12× 膨胀
```
（sheet 为 2172×724 PNG，单张 0.75–2.0 MB；武器命中表单张 2.0 MB × 5 份 = 10.3 MB）

#### 建议（**两种，请裁决一种**）

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| **A（我倾向）** | 允许 **sheet 共享**：同一物理文件只复制**一份**（中性文件名），多个 Asset 条目各自携带 `frameRect`。构建脚本的唯一性检查放宽为"**不同物理文件不得同名**；同一文件可被多个 ID 引用"。 | 需修改构建脚本的唯一性判据与 manifest 校验（同一 `runtimeFile` 允许多 ID 共享） |
| **B** | 按 ID 复制 N 份（如 `GFX-V21-WPN-PRISM__sheet.png`），保持 basename 唯一与现有流水线不变。 | **运行时体积 +70.6 MB**，且同一张图在内存中可能被加载多次 |

**我倾向 A**：① 与规范 §2/§4.2 的"sheet + frameRect"模型一致；
② 避免 12× 体积膨胀；③ v2.0 已要求"不悄悄切占位/不得复用以假乱真"，
共享同一 sheet 的不同格子**不构成**语义复用（格子内容本就不同）。
但**这属于 schema 与流水线设计**，我不擅自决定，**请裁决**。

#### 状态变更记录

* 2026-10-17：登记，状态 `待确认`（阻塞 B0 的 manifest 生成与 hash 门禁）。

### FV21-02　必填文案 key `objective.timeLimit` 的中文值缺失

**级别**：P1
**状态**：**待确认**
**发现时间**：2026-10-17（B0 §2.2 写入 strings 时）

#### 现象

蓝图 §2.2 要求：

> `strings_zh_CN.json`：增加 09 §3.1 全部 key，且**补齐** `objective.survive`、
> `objective.bossIncoming`、`objective.defeatBoss`、**`objective.timeLimit`**。
> 门禁：**UI 不显示 key、UP- ID 或裸剩余秒数**。

其中 `objective.survive` / `bossIncoming` / `defeatBoss` **已存在**于
`strings_zh_CN.json`（v2.0 遗留）✓，但 **`objective.timeLimit` 不存在**，
且**产品冻结表 §3.1 只列出了 11 个 key，其中没有 `objective.timeLimit`** ✗

**已核查**：`Spec/01_产品/v2.1/` 全文与 `Spec/03_素材/v2.1/` 均**未给出**
`objective.timeLimit` 的中文原文；冻结表 §3.1 的表格内确实没有这一项。

#### 依据

* `Spec/02_技术/v2.1/02_代码改造蓝图.md` §2.2（要求补齐该 key）；
* `Spec/01_产品/v2.1/Warship_v2.1功能冻结表.md` §3.1（仅 11 个新 key，不含它）。

#### 影响

* 该 key 用于 **190 秒判负**（`RunEnded(reason=timeLimit)`）时的目标提示。
  蓝图门禁明确**禁止 UI 显示裸秒数或 key**，因此**必须有中文原文**；
* **不阻塞 B0 其余部分**（我已先补齐冻结表给出的 12 个 key + `player.json`
  改名），仅在实现到"190 秒失败"的提示与 Golden 时需要它。

#### 建议

请产品给出 `objective.timeLimit` 的简体中文原文（与 `objective.survive` /
`bossIncoming` 的语气保持一致）。**我不擅自编造玩家可见文案**。

### FV21-03　`impactDamageRadius` 被要求显式配置，但数值缺失

**级别**：P1（阻塞 B2 的 Plasma 爆裂半径）
**状态**：**待确认**
**发现时间**：2026-10-17（B0 §2.2 写入 `weapons.json` 的 `mainWeaponStyles` 时）

#### 现象

蓝图 §3.4 明确要求：

> **Plasma：首命中即销毁；伤害半径由显式 `impactDamageRadius` 配置，
> 绝不从 96px 图片尺寸推断。**

但**该字段的数值在整个 v2.1 文档中都没有给出** ✗
（`grep -rn "impactDamageRadius"` 在 `Spec/01_产品/v2.1/`、`Spec/02_技术/v2.1/`、
`Spec/03_素材/v2.1/` 中**只命中蓝图这一处要求**，没有任何数值表）。

可对照的只有**视觉尺寸**（冻结表 §3「命中特效尺寸」）：
Prism 72×72、Arc 80×80、**Plasma 96×96**、Needle 60×60、Missile 92×92。
但蓝图**恰恰禁止**把它当作伤害半径 ✗。

#### 影响

* **阻塞 B2**：Plasma 的爆裂伤害范围无法实现（不能凭空取数，也不能用图片尺寸）；
* 其余四种形态的碰撞规则（穿透/弹跳/追踪）**都有明确规则**，只有 Plasma 缺这一个数 ✗；
* **不阻塞 B0**：我已把 `mainWeaponStyles` 的其余字段（倍率、穿透、弹跳、追踪、
  素材 ID、命中 cue、弹体/命中视觉尺寸）全部按冻结表写入，
  **`impactDamageRadius` 留空待裁决**，未编造数值。

#### 建议

请产品给出五种形态（至少 Plasma）的 **`impactDamageRadius`（logical px）**。
若只有 Plasma 需要，也请明确其余四种是否取 0（首命中即销毁且无范围伤害）。

#### 状态变更记录

* 2026-10-17：登记，状态 `待确认`（B0 已按可确定部分落地，未阻塞）。
