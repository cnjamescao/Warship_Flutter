## 一、当前代码的实际缺陷（已确认）

`lib/game/core/game_runtime.dart` 约 584–608 行：

```dart
for (final request in event.attackRequests) {
  bus.emit(EnemyAttackFired(...));            // ① 立刻发 Fired
  if (request.telegraphSeconds > 0) {
    bus.emit(EnemyAttackTelegraphed(...));    // ② 同一步发预警
  }
  _spawnEnemyAttack(request);                 // ③ 同一步生成伤害实体
}
```

**违反**：「所有 `telegraphSeconds > 0` 的敌机攻击在 t=0 发
`EnemyAttackTelegraphed` … 在 `startedAt + telegraphSeconds` **前不得发
`EnemyAttackFired`、生成伤害实体或结算伤害**。到期同一步才发 Fired 并生成实体。」

即当前是「预警与发射同步发生」，预警时长对玩家**完全无效**。

## 二、规范要求的完整合同（逐条）

### 2.1 时序（Domain / Runtime）
1. `telegraphSeconds > 0` 的攻击：**t=0 只发 `EnemyAttackTelegraphed`**，
   并以当时的 `origin`、`aimTarget`、`shape` 建立**不可变待执行攻击**。
2. `startedAt + telegraphSeconds` **之前**：不得发 `EnemyAttackFired`、
   不得生成伤害实体、不得结算伤害。
3. **到期同一步**：发 Fired **并**生成实体。

### 2.2 取消 / 冻结规则（必须覆盖）
以下情形待执行攻击**必须取消/冻结且不得残留**：
* 源敌机被移除；
* 风险门开启；
* 胜利锁定；
* 重开；
* 任何非 `Playing` 状态（含暂停）。

### 2.3 锁定坐标规则
* `sniper_line`：`origin` / `aimTarget` **均在 t=0 锁定**；
  线形预警沿该射线**裁切到逻辑世界边界**（1920×1080）。
* `bomber_drop`：落点固定为 **t=0 的 origin**。

### 2.4 `bomber_drop` 危险区（阶段一既定功能，必须实现）
| 项 | 值 |
| --- | --- |
| 预警 | **0.40 s**（由 `TelegraphView` 负责） |
| 危险区半径 | **90** |
| 持续 | **2.2 s** |
| 伤害 | **每 0.25 s，每目标至多 8 点** |
| `warningSeconds` | **0**（不得重复预警） |

### 2.5 渲染
* 快照以**独立不可变 `TelegraphView`** 公开预警 ——
  **禁止折叠进 `EntityView`**，**禁止表现层猜测目标**。
* 预警与危险区均处于**背景之上、实体之下**（即**在敌机下层**）。
* **只允许 manifest 绑定的正式素材及正式 danger pattern**；
  **不得用 Canvas 几何替代资源**。
  （注：F-12 仍要求"保留几何形状/动态收缩"作为第二识别维度，
   与"不得用几何替代**素材**"并不冲突 —— 素材是主体，几何可作叠层。）
