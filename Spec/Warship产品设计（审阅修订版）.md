# Warship 产品技术规格（审阅修订版）

> 版本：v1.1-review  
> 基线：`Warship产品设计.md` v1.0（保留不改）  
> 变更标记：**[修订]** 表示纠正或重述原规格；**[新增]** 表示新增的需求/验收项；**[澄清]** 表示代码已实现的边界；**[提议]** 表示尚未实现，不能作为当前版本已交付功能。  
> 本文是审阅后的目标规格，不代表这些改进已经写入应用代码。

## 1. 定位与交付边界

Warship 是一款在 macOS 桌面端运行的单机复古太空射击游戏。玩家用键盘左右移动飞船并连续射击，清除持续下压的敌方舰队以获得分数。

**[修订]** 当前仓库的实际交付平台是 macOS；Flutter/Flame 具备跨平台潜力并不等于移动端已受支持。Android、iOS、Web、Windows 和 Linux 平台工程、触摸控制与手柄控制均不在当前交付范围。

| 状态 | 当前版本能力 |
| --- | --- |
| 已实现 | 菜单、开始/重开、左右键盘移动、空格连发、敌人舰队、三条生命、计分、内存内最高分、HUD、结束遮罩 |
| 未实现 | 最高分持久化、暂停、音频、敌人攻击、道具、排行榜、移动端输入 |
| [新增] 本版质量目标 | 调整窗口与输入焦点变化时仍保持正确、可预测、不崩溃的游戏状态 |

## 2. 用户流程

### 2.1 启动与菜单

应用加载 `ship.png` 与 `alien.png`，并在游戏画布尺寸有效后创建飞船与首波敌人。初始状态为 `menu`：背景、飞船和舰队可见但逻辑不推进；遮罩显示 **Alien Invasion** 与 **Play**。

**[澄清]** 资源和画布尺寸的准备顺序不保证，初始化必须在两者都完成后仅执行一次。

### 2.2 对局

点击 Play 后进入 `playing`：初始分数为 0、生命为 3、舰队速度为 90 px/s。玩家可按住左/右动作移动，按住空格以约 0.28 秒冷却持续射击。子弹命中敌人时，**每个唯一敌人**获得 50 分。

**[修订]** “每个唯一敌人”是计分契约；同一帧的多颗子弹命中同一敌人只能移除一次并获得一次分数。

敌人整体横向移动；碰到任一边界时，舰队反向并整体下移 30px。舰队清空后生成新一波，基础横向速度递增 10 px/s。

### 2.3 掉命、结束与重开

飞船与敌人相撞，或任一敌人到达底边时，当前局最多损失一条生命。剩余生命大于 0 时清除子弹/敌人、飞船回到底部中央并生成新舰队；生命为 0 时进入 `gameOver`，显示最终分数与 Play Again。重开重置分数、生命、速度与输入状态，但保留当前进程的最高分。

## 3. 状态机与数据契约

| 状态 | 规则循环 | 遮罩 | 可用输入 |
| --- | --- | --- |
| `menu` | 停止 | 标题 + Play | 开始按钮 |
| `playing` | 移动、射击、碰撞、计分 | 无 | 左、右、射击；[提议] 暂停 |
| `gameOver` | 停止 | 结算 + Play Again | 重开按钮 |
| [提议] `paused` | 停止 | 暂停菜单 | 恢复/重开 |

游戏层拥有唯一的事实来源：`score`、`highScore`、`lives`、`state`。Flutter UI 只订阅、不得写入这些值。

**[新增]** 对局状态变更必须以确定时序对 UI 可见；不得依赖未受控的帧末回调来保证正确性。游戏被销毁后，不得再向 UI 发通知。

## 4. 输入规范

| 动作 | 按键 | 契约 |
| --- | --- | --- |
| 左移 | `←` 或 `A` | 两键任意一个仍按下即保持左移 |
| 右移 | `→` 或 `D` | 两键任意一个仍按下即保持右移 |
| 射击 | `Space` | 按住连续发射，冷却为 0.28s |
| [提议] 暂停 | `Esc` 或 `P` | 切换暂停，不改变分数和世界坐标 |

**[新增]** 窗口失焦、进入菜单/结束、暂停和销毁时必须清空输入状态，防止粘键。左右同时按住时移动量为 0，不应积累位置误差。

## 5. 画布与布局规范

**[修订]** 不再把“任意窗口尺寸均可正常游玩”作为隐含假设。当前像素尺寸为：飞船 64×48、敌人 48×40、子弹 4×12，低于这些约束的画布不能安全承载当前规则。

**[新增] 推荐方案：固定逻辑画布。** 游戏规则在固定虚拟尺寸（建议 800×600）下运行，窗口通过保持比例的 viewport 显示。窗口尺寸变化只影响显示缩放，不改变游戏世界坐标。

| 规则 | 验收标准 |
| --- | --- |
| 常规 resize | 背景、HUD 与 viewport 正确适配；飞船、子弹和舰队不越界 |
| 窗口过小 | 显示缩小或“窗口过小”提示；不抛异常、不连续掉命 |
| 大 `dt` / 高波次 | 舰队触边后回到有效边界，再反向并下移；不会长期在屏幕外 |

**[提议]** 若不使用虚拟画布，则 resize 时暂停并按新边界约束飞船/子弹，同时重新创建或按比例重排舰队；不得只调整背景。

## 6. 游戏规则与数值

| 参数 | 当前值 | 状态 |
| --- | ---: | --- |
| 飞船速度 | 420 px/s | 已实现 |
| 子弹速度 | 520 px/s | 已实现 |
| 子弹冷却 | 0.28 s | 已实现；**[新增]** 提为命名常量 |
| 敌人初始速度 | 90 px/s | 已实现 |
| 每波加速 | 10 px/s | 已实现；**[新增]** 提为命名常量 |
| 敌人下移 | 30 px | 已实现 |
| 单敌人得分 | 50 | 已实现；**[修订]** 基于唯一击毁数量结算 |
| 初始生命 | 3 | 已实现；**[新增]** 提为命名常量 |
| 飞船底部边距 | 20 px | 已实现；**[新增]** 提为命名常量 |
| [提议] 敌人速度上限 | 待产品确定 | 防止无限波次超过可反应范围 |

**[新增]** 所有手感数值必须集中在不可变配置中。运行时规则仍需使用 `dt`，并对异常大的 `dt` 进行可预期处理（例如限制单帧模拟步长或使用固定步长）。

## 7. 架构

当前结构：Flutter `GameScreen` 负责 `GameWidget + HUD + Overlay`；`WarshipGame` 同时承担资源加载、输入、状态、实体列表、移动、碰撞、计分和 UI 通知；`PlayerShip`、`AlienEnemy`、`Bullet` 为表现组件。

**[修订]** 这适用于当前小型原型，但不应被定义为长期架构目标。推荐演进为：

```text
GameScreen (Flutter 表现与生命周期)
  └─ WarshipGame (Flame 场景协调)
       ├─ GameSession / ScoreStore（状态、计分、持久化）
       ├─ InputController（动作状态、失焦清理）
       ├─ FleetController（生成、边界、难度）
       ├─ CollisionResolver（唯一命中与伤害裁决）
       └─ Flame components（飞船、敌人、子弹的显示/局部行为）
```

**[新增] 生命周期契约：** `GameScreen` 拥有游戏实例；离开页面时释放它所拥有的通知器、监听和排队任务。资源所有权必须唯一、可测试。

## 8. 持久化、可访问性与体验路线

| 优先级 | 需求 | 状态 / 验收 |
| --- | --- | --- |
| P1 | 输入与 resize 健壮性 | [新增] 见第 4、5 节的验收标准 |
| P2 | 最高分持久化 | [提议] 使用本地键值存储；启动读取、刷新时写入；失败不阻塞对局 |
| P2 | 暂停 | [提议] `Esc`/`P`、失焦自动暂停可配置 |
| P2 | 音效与静音 | [提议] 射击、命中、掉命、结束至少各一类反馈 |
| P3 | 难度曲线 | [提议] 速度上限 + 敌人类型/开火频率，而非无限加速 |
| P3 | 移动端 | [提议] 先定义触摸控制、屏幕适配与平台支持后再创建目标工程 |

## 9. 质量门禁与测试

当前门禁：`flutter analyze`、`flutter test`。当前测试验证菜单初值、开始、输入不崩溃、无操作最终结束、重开和一个 UI 点击流程。

**[修订]** “测试全绿”仅说明当前六项测试通过，不等价于全部规则正确或 macOS 构建已验证。

**[新增] 必测回归项：**

1. 两颗子弹同帧命中同一敌人：只移除一次、得 50 分。
2. `A + ←` 或 `D + →` 同时按下并先松开其中一个：动作持续到两个键都松开。
3. 失焦后不再移动或射击。
4. 最小、窄、高宽比极端和常规 resize：不抛异常、不越界、不连续掉命。
5. 高速度和大 `dt`：舰队仍正确回边、反向、下移。
6. 计分、生命、结束遮罩和重开文案：测试 UI 可见结果，而不只检查无异常。
7. 初始化完成：使用确定性的加载完成条件，移除测试中的固定 500ms sleep。

**[提议]** CI 在每个合并请求运行格式检查、`flutter analyze`、`flutter test`；当 Xcode 环境可用时加入 `flutter build macos --debug`。

## 10. 运行说明

```bash
flutter pub get
flutter run -d macos
flutter analyze
flutter test
```

控制方式：`←`/`A` 左移，`→`/`D` 右移，`Space` 连续射击。  
**[新增]** macOS 原生构建还要求本机 Xcode 已完成首次启动和许可配置；这属于开发环境前提，不是 Dart 规则的一部分。

## 11. 变更摘要

| 原 v1.0 主题 | 本次修订 |
| --- | --- |
| 将当前实现与演进建议混合 | 明确分成“已实现 / 未实现 / 提议” |
| resize 仅作为已知限制 | 升级为 P1 质量需求，给出固定逻辑画布的推荐方案 |
| 输入仅描述单键事件 | 补充别名组合、失焦和清理的动作契约 |
| 计分描述为命中数 | 修订为“唯一击毁敌人”并增加回归要求 |
| UI 同步描述为既定优化 | 增加确定时序与生命周期要求，避免把实现细节当架构目标 |
| 测试宣称覆盖较广 | 精确描述当前覆盖，并列出缺失的确定性回归测试 |
| 架构只评价 God Object | 规定渐进式职责拆分和资源所有权边界 |
