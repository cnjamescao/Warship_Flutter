## 1. 领域状态与事件

| 组件 | 新职责 | 必须事件/快照 |
| --- | --- | --- |
| `UpgradeSystem` | 阈值到达后从合法池按 run seed 抽 1 项并立即应用 | `AutoUpgradeGranted{upgradeId,level,weaponStyleId?}` |
| `RiskGateSystem` | gate 到时从合法结果按 run seed 抽 1 项，原子应用代价/收益，不改变 phase | `AutoRiskResolved{gateId,occurrenceOrdinal,optionId,resultNoticeOrdinal}` |
| `RunState` | 保存本局强化历史、主弹道形态、清场确认计时 | 不可变快照字段 `upgrades`,`weaponStyle`,`clearState` |
| `DirectorSystem` | 暴露“所有计划行已消费且无未来 Boss” | `DirectorCompleted` |
| `VictorySystem` | 验证清场四条件，开始 0.8s 确认；确认期内新威胁出现则取消 | `SectorClearStarted/Cancelled/Confirmed` |
| `PresentationSystem` | 只消费领域事件，驱动动效与 HUD 提示 | `EffectView`、`UpgradeToastView`、`MedalView` |

## 2. 不可变规则

1. 自动强化和风险门自动结算均不允许改变 `GamePhase`，不得冻结逻辑时钟。正常对局的 `upgradeDraft`、`riskGate` 状态必须不可达。
2. 同 seed、同 InputFrame 必须得到同一升级、主弹道形态、风险结果、清场结算时刻及音频条件参数。
3. 清场要求：Director 完成、无敌人、无敌方投射物、无危险区、无 pending attack；Boss 未来计划存在时不得清场胜利。
4. Boss HP=0 的原子胜利优先于清场逻辑。
5. 动效永不修改碰撞、伤害、速度或攻击节奏；击毁后的表现不能继续造成伤害。

## 3. 逻辑顺序、状态机与取消条件

每个 `Playing` 固定步按下面顺序执行，避免“先结算、后生成威胁”的一帧误胜利：

1. 处理输入、移动和既有攻击；
2. 处理 Director/Boss 计划行并产生本步的新实体、危险区与待攻击；
3. 处理碰撞、伤害、死亡、掉落和强化阈值；
4. 如跨过强化阈值，调用 `UpgradeSystem.grantOne(seed, eligiblePool)`，同步写入 `RunState` 并发 `AutoUpgradeGranted`；如 gate 到时，随后调用 `RiskGateSystem.resolveOne(seed, legalOptions)`，同步写入 `RunState` 并发 `AutoRiskResolved`；两者均不等待输入。
5. 构建“本步末”的 `ThreatSnapshot`；只有它满足清场四条件时才推进 `VictorySystem`；
6. 最后基于不可变领域事件派生 `EffectView`、`UpgradeToastView`、`MedalView`。

`VictorySystem` 状态只允许 `idle → confirming → confirmed`：

- `idle`：四条件不全，不显示清场倒数。
- `confirming(startedAt)`：首个满足条件的本步进入，固定时长 `0.8s`；产生 `SectorClearStarted`。
- `confirmed`：只有已连续满足 `0.8s` 才进入；产生 `SectorClearConfirmed` 并交给既有结果页。
- 在 `confirming` 中，任何一项条件反转、`GamePhase != Playing`、玩家死亡、Boss 生成或 Boss HP 尚大于零，都必须立即回到 `idle` 并产生 `SectorClearCancelled`。暂停不是倒计时推进时间；恢复后以原始 `startedAt` 加有效 Playing 时间计算。

不得依据 HUD “剩余数”、wall clock 或敌人已消失的单一条件宣布胜利。

## 4. 数据模型

`WeaponStyleSpec{id,weight,projectileAssetId,impactAssetId,cueId,damageMultiplier,speedMultiplier,radiusMultiplier,pierce,bounce,homing}`；每局一旦首次取得主形态即锁定，后续只能升级同系参数。

`EffectSpec{assetId,frameRects,fps,totalMs,anchor,blendMode,maxConcurrent,mergeWindowMs,reduceMotionMs,transformTimeline}`；每个动效至少 3 个可见阶段。`transformTimeline` 仅可控制表现层的 opacity/scale/rotation/position，不可反写战斗规则。

`MedalSpec{tier,assetId,cueId,transformTimeline}`；禁止三个 tier 指向同一个运行时文件。

`ThreatSnapshot{directorCompleted,hasFutureBossPlan,enemyCount,enemyProjectileCount,hazardCount,pendingAttackCount,bossAlive}`；它是 `VictorySystem` 的唯一输入。`directorCompleted && !hasFutureBossPlan && enemyCount == 0 && enemyProjectileCount == 0 && hazardCount == 0 && pendingAttackCount == 0 && !bossAlive` 才能开始清场确认。

### 4.1 自动强化抽取合同

```text
eligible = allUpgradeSpecs where isEligible(runState, spec)
assert eligible.isNotEmpty
chosen = deterministicWeightedPick(runSeed, upgradeGrantOrdinal, eligible)
apply(chosen) exactly once
if chosen grants first main weapon style:
  style = deterministicWeightedPick(runSeed, styleGrantOrdinal, Prism/Arc/Plasma/Needle/Missile)
  lock style for this run
emit AutoUpgradeGranted(chosen.id, chosen.newLevel, style?.id)
```

- `upgradeGrantOrdinal` 与 `styleGrantOrdinal` 为快照字段；重放、暂停、重新绘制不得增加 ordinal。
- `isEligible` 必须排除达到上限、前置不满足、与已有强化互斥的项；若池为空，视为内容配置错误，测试环境抛可读异常，Release 记入阻断诊断，不能静默无强化。
- 非首次主弹道强化只提升当前已锁定形态的参数；不得中途更换形态，也不得因通知 view 重建而再次应用。

### 4.2 配置最小形式

### 4.1A 风险门自动结算合同【新增 v2.1-R2】

`RiskGateSystem.resolveOne` 的合法池来自同一份 `risk_gates.json`；结果顺序固定为配置 `optionId` 的字典序，等权选择通过带标签的随机调用 `riskGate:<gateId>:<occurrenceOrdinal>` 完成。`RG-OVERLOAD` 在 `playerHp <= 35` 时剔除。选中后必须在同一逻辑步先验证代价与目标，再一次性写入状态、发事件与登记历史；不得产生 UI timeout、点击外部、清弹、暂停或停止出生副作用。Overload 的稀有卡同样通过单卡确定性抽取，不能返回 DraftOffer。

`RunState` / 回放摘要至少保存 gateId、occurrenceOrdinal、optionId、Overload 卡 ID（若有）、开始/结束时间与 resultNoticeOrdinal。相同 seed、相同输入必须逐字段一致；若合法池为空，开发/测试抛具备 gateId 与候选原因的异常，Release 作为内容阻断。

```text
weaponStyle: { id, weight, projectileAssetId, impactAssetId, cueId,
  damageMultiplier, speedMultiplier, radiusMultiplier, pierce, bounce, homing }
upgrade: { id, weight, maxLevel, prerequisites, exclusions, effect }
manifestAsset: { id, kind, path, sheetSize, frameRect, sha256, contentVersion }
```

内容配置只存玩法参数与资源 ID；具体 Widget、Canvas 或 Flame 类名不进入配置。

### 4.3 首发五种主弹道配置

首发权重均为 `20`。数值是相对于 v2.0 基础主弹的乘数；首次形态授予后立即生效，后续同系强化只能增加本行已有机制，不能改写为另一行。

| styleId | damage | speed | radius | 特性 | projectileAssetId / impactAssetId / cueId |
| --- | ---: | ---: | ---: | --- | --- |
| `prism` | 1.00 | 0.95 | 1.00 | `pierce=1` | `GFX-V21-WPN-PRISM` / `GFX-V21-WPN-PRISM-IMPACT` / `SFX-V21-WPN-PRISM-IMPACT` |
| `arc` | 0.82 | 1.00 | 0.90 | `bounce=1` | `GFX-V21-WPN-ARC` / `GFX-V21-WPN-ARC-IMPACT` / `SFX-V21-WPN-ARC-IMPACT` |
| `plasma` | 1.22 | 0.78 | 1.35 | 无穿透、无追踪、爆裂半径 84 logical px | `GFX-V21-WPN-PLASMA` / `GFX-V21-WPN-PLASMA-IMPACT` / `SFX-V21-WPN-PLASMA-IMPACT` |
| `needle` | 0.72 | 1.48 | 0.62 | `pierce=2` | `GFX-V21-WPN-NEEDLE` / `GFX-V21-WPN-NEEDLE-IMPACT` / `SFX-V21-WPN-NEEDLE-IMPACT` |
| `missile` | 1.08 | 0.86 | 1.05 | `homing=true` | `GFX-V21-WPN-MISSILE` / `GFX-V21-WPN-MISSILE-IMPACT` / `SFX-V21-WPN-MISSILE-IMPACT` |

`pierce` 表示额外可命中的目标数；`bounce=1` 表示只允许一次转向目标；`homing=true` 使用现有最近合法敌人的锁定规则。没有合法敌人时 Missile 直线飞行，绝不创建新目标或改变 RNG 消耗。

`impactDamageRadius` 固定写入配置：Prism / Arc / Needle / Missile=`0`，Plasma=`84`。Plasma 直接目标只受一次 `effectiveDamage`；半径内最多 4 个其他合法敌人按距离、EntityId 稳定排序，各受 `floor(effectiveDamage×0.55)`，不得命中玩家、拾取物、已移除实体或直接目标。

### 4.4 玩家受击与 Boss 命中音频合同【新增 v2.1-AUDIO】

`PlayerDamaged` 只派生稳定枚举 `damageLayer=shield|hp`，不再同时携带/消费旧的 `shieldDamageGt`、`hpDamageGt` 音频条件。v2.1 manifest 仅保留：`shield → SFX-V21-SHIELD-HIT`、`hp → SFX-V21-HP-HIT`；旧 `SFX-PLAYER-SHIELD-HIT` 与 `SFX-PLAYER-HP-HIT` 可留在 v2.0 发布版本，但不得在 v2.1 对局的 eventBindings 中出现。

每个 `WeaponHit` 必须由 Domain 在命中时写入不可变 `targetIsBoss: bool`；Presentation 与 AudioDirector 不得由 `targetEnemyId` 字符串、Widget 或画面状态推断。v2.1 manifest 路由固定为：`targetIsBoss=true → SFX-V21-BOSS-HIT`，`targetIsBoss=false → SFX-EN-HIT`。Boss cue 的 `priority=90`、`maxVoices=1`、`minRetriggerMs=140`；触发后对 impact 子总线 duck `-6dB`、释放 `110ms`，BGM 不受影响。事件/快照/回放均须保留 `targetIsBoss`，避免重放时不同路由。

## 5. 渲染与接入

- 渲染顺序：机体底层 → 机体状态动效 → 命中/击毁 → HUD；警告与危险区保留其既定优先级。
- 只能按 v2.1 manifest 的 Asset ID、帧区间和 cue ID 加载；不得 Canvas 补画、不得使用回退剪影作为正常态。
- 自动强化与风险结果提示在 Flutter HUD，不吞输入；只能以无文字的 `ResultNoticeView.emblemAssetId` 绘制，动效在 Flame/表现层，以不可变 `EffectView` 驱动。
- Release 中任一必需 v2.1 素材加载失败即记录 Asset ID 并使素材验收失败。

## 7. 实施与资源边界

1. B0 先新增 v2.1 manifest；每个 ID 必须指定真实 `path`、`frameRect`、`kind`、`contentVersion` 和 audit hash。不得把 sheet 的完整尺寸直接当成单帧尺寸。
2. 每项素材只有在素材清单标记 `asset-reviewed` 后才可进入预加载列表；音频还必须完成试听与响度签收。
3. 不得将“素材缺失时的程序绘制”做成正常回退。开发/测试环境可快速失败并输出 Asset ID；Release 必须作为验收失败处理。
4. 所有新增 public 类型、事件、状态字段及非显然的时序/取消分支均须附简体中文注释，说明业务原因、时序单位、所有权与取消条件；禁止重复代码字面意思的注释。
