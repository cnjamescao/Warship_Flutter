# 01｜技术架构与模块设计

## 1. 架构目标

v2.0 必须满足四个工程目标：规则确定性、内容数据化、渲染与规则分离、生命周期可回收。Flutter 负责应用壳、HUD、菜单、无障碍和平台生命周期；Flame 负责逻辑世界、实体渲染和触摸/键盘到游戏输入的桥接；纯 Dart Domain 负责所有可复现战斗规则。

~~~mermaid
flowchart TB
  Flutter[Flutter App / GameScreen / HUD] --> Bridge[Presentation Bridge]
  Bridge --> Runtime[GameRuntime]
  Runtime --> Domain[Domain Systems]
  Runtime --> Content[Content Repository]
  Runtime --> Infra[Audio / Storage / Asset Loader]
  Domain --> Events[Typed Domain Events]
  Events --> Bridge
  Events --> Infra
  Content --> Domain
  Flame[Flame World / Components] <--> Bridge
~~~

依赖只允许从外层指向内层：`app/presentation/infrastructure → domain/core/content`。`domain` 禁止 import Flutter、Flame、音频插件、文件系统或 Widget；它只接收值对象、输入快照和确定性随机源。

## 2. 模块职责与公开接口

| 模块 | 必须负责 | 禁止负责 | 关键输出 |
| --- | --- | --- | --- |
| `core` | Run ID、种子、逻辑时钟、状态、固定 dt、事件序号 | 伤害公式、资源播放 | `RunContext`、`GameClock`、`GamePhase` |
| `content` | 加载、解析、版本校验、ID 引用校验、只读配置 | 运行时状态、随机抽卡 | `ContentCatalog` |
| `domain` | 移动、目标选择、伤害、升级、Director、Boss、掉落、胜负 | Sprite、Widget、文件 I/O | `SimulationState`、`DomainEvent[]` |
| `presentation` | Flame Components、视觉状态、HUD ViewModel、输入转换 | 修改配置、直接计算伤害 | `RenderSnapshot`、`UiCommand` |
| `infrastructure` | 音频限频、存档、资源预载、平台失焦、性能采样 | 产品规则 | 接口实现 |
| `app` | 注入依赖、首页/设置/结算路由、SafeArea | 直接遍历战斗实体 | 生命周期命令 |

### 2.1 必须存在的抽象

以下是语义接口，不强制使用完全相同的 Dart 声明。

| 抽象 | 输入 | 输出 | 契约 |
| --- | --- | --- | --- |
| `GameRuntime` | 单帧 `InputFrame`、`dt` | `RenderSnapshot`、事件流 | 仅 `Playing` 推进逻辑；不可重入 |
| `ContentRepository` | content version | `ContentCatalog` 或结构化错误 | 失败不能进入 `Briefing` |
| `RandomSource` | 无 | `nextInt/nextDouble` | 由 `run_seed` 初始化；可记录/回放 |
| `InputGateway` | 键鼠/触摸/焦点事件 | `InputFrame` | 不保留已失焦按键 |
| `AudioPort` | `AudioCue` | 无 | 合并、限频、静音、暂停/恢复正确 |
| `ProgressStore` | settings/records | 成功或可恢复失败 | 读写失败不可阻断游玩 |
| `Clock` | 原始帧间隔 | 固定逻辑步 | 最大补偿 50 ms，禁止巨帧穿透 |

## 3. 状态机、生命周期和资源所有权

### 3.1 运行状态

| 状态 | 允许的命令 | 逻辑时钟 | 输入 | 离开时必须做什么 |
| --- | --- | --- | --- | --- |
| `Home` | Start、OpenSettings | 停止 | UI | 释放上一局 World 引用 |
| `Loading` | Cancel、Retry | 停止 | UI | 取消未完成资源任务；不得留下音频 |
| `Briefing` | Skip（仅倒计时后半段） | 仅表现时钟 | 移动/攻击无效 | 创建本局状态，初始化 seed、配置、对象池 |
| `Playing` | 移动、Dash、Pause | 全部逻辑时钟 | 全部战斗输入 | 正常推进 |
| `UpgradeDraft` | SelectCard | **全部逻辑冻结** | 只接受卡片/UI | 选择后一次性应用升级并回 Playing |
| `RiskGate` | SelectRisk | **全部逻辑冻结** | 只接受选项/UI | 超时只执行 `RG-SUPPLY` |
| `Paused` | Resume、Restart、Quit | **全部逻辑冻结** | 只接受菜单/UI | 不清除局内对象 |
| `Result` | Restart、Home | 停止 | 只接受结算/UI | 停止所有循环音/危险音 |

`AppLifecycleState.inactive/paused/detached`、浏览器 `visibilitychange(hidden)`、窗口失焦均必须提交同一个 `PauseRequested(source)` 命令。重复 Pause 命令必须幂等。恢复时不自动继续，玩家点击“继续”才回 `Playing`。

### 3.2 资源所有权

- 一次 `RunSession` 独占：World、实体注册表、对象池借出对象、seed、事件序号、战斗音频句柄。
- 重新开始先 `dispose RunSession`，再创建下一局；旧对象不得再向 HUD、音频或 Flame World 发事件。
- `GameScreen.dispose` 负责取消资源加载、解绑生命周期观察者、清空输入、停止所有由本屏创建的音频。
- Component 的 `onRemove` 仅处理表现层清理；规则状态删除必须由 Domain 的实体生命周期先决定。

## 4. 固定步进与单帧顺序

渲染帧可变，逻辑必须固定为 `1/60 s`。渲染帧 dt 先 clamp 至 50 ms，再累加到 accumulator；单个渲染帧最多执行 3 个逻辑步，超出的 accumulator 丢弃并记录性能告警，防止后台回来后追算伤害。

每个逻辑步必须严格按以下顺序：

1. 接收并锁定本步 `InputFrame`；处理边沿命令（暂停、选卡、风险门）。
2. 若当前不为 `Playing`，只生成 UI/表现快照，结束本步。
3. 更新冲刺、Buff、护盾恢复、连击衰减、Director 与 Boss 的**计时器**。
4. 依据已锁定输入计算玩家移动意图；夹紧到逻辑世界边界。
5. 更新敌人、Boss、投射物、危险区、无人机；仅创建“待生成命令”，不得在遍历集合时直接插入。
6. 执行目标选择与武器发射；将新增实体加入待提交队列。
7. 收集碰撞对；按碰撞层和事件序号排序，生成伤害意图。
8. 合并伤害、应用无敌/护盾/HP、死亡、经验、掉落、分数和状态转移。
9. 提交实体新增/移除、发出不可变 `DomainEvent`、生成 `RenderSnapshot`。

任何步骤都不得由 Component 绕过 Domain 直接扣 HP、加分、抽卡或切状态。

## 5. 运行时系统清单

| 系统 | 责任 | 主要读取 | 主要写入 |
| --- | --- | --- | --- |
| `PlayerSystem` | 移动、冲刺、护盾恢复、死亡 | Input、PlayerConfig | 玩家状态、事件 |
| `TargetingSystem` | 选目标与前方回退 | 实体索引 | 武器目标 |
| `WeaponSystem` | 射击、冷却、升级效果 | Weapon/Upgrade Config | 投射物请求 |
| `EnemySystem` | 敌人路径、攻击、预警 | Enemy Config、Director | 敌人/预警/投射物请求 |
| `BossSystem` | 入场、阶段、招式循环、弱点 | Boss Config | Boss 状态、事件 |
| `CollisionSystem` | Broad phase、hit gate、伤害意图 | 碰撞层 | DamageIntent |
| `DamageSystem` | 合并、结算、防重入 | DamageIntent | HP、死亡事件 |
| `RewardSystem` | 经验、分数、连击、精英核心 | DeathEvent | 玩家资源/草案请求 |
| `UpgradeSystem` | 候选、过滤、选择、应用 | Catalog、PRNG | 玩家 modifier |
| `DirectorSystem` | 波次、动态数量修正、风险门 | Wave Config、指标 | Spawn/Risk 请求 |
| `PresentationSystem` | 事件转显示状态/特效 | DomainEvent | Snapshot/AudioCue |

## 6. Flame 与 Flutter 的实现边界

- Flame Component 以 `entityId` 绑定 Domain 实体；每帧只读取 `RenderSnapshot` 更新位置、动画、可见性和视觉状态。
- HUD 由 Flutter `ValueListenable`、`Stream` 或等价不可变 ViewModel 驱动；禁止 Widget 直接读取 Flame Component 私有字段。
- 背景、粒子、残影等纯表现对象可不创建 Domain 实体，但必须由 `DomainEvent` 触发且受性能上限控制。
- 碰撞判定放在 Domain；Flame `HasCollisionDetection` 可以用于调试可视化，但不得成为规则唯一来源。
- 所有 UI 覆盖层必须在 Flutter 层；World 不承担升级卡、风险门、暂停面板和结算按钮。

## 7. 错误、日志与调试

| 场景 | 用户行为 | 工程行为 |
| --- | --- | --- |
| 内容配置校验失败 | Loading 显示“资源版本错误，请重试”；可返回首页 | 记录具体 ID/字段；禁止开始对局 |
| 单个视觉资源失败 | 使用占位 sprite，不影响规则 | 一次性记录 asset ID，不无限重试 |
| 音频失败 | 静默继续 | 记录 cue/平台；不抛到战斗循环 |
| 存档失败 | 使用内存默认值 | 记录错误，下一次仍可尝试写入 |
| 不变量失败（如重复实体 ID） | 安全结束当前局并返回 Result | Debug/assert 失败；生产记录 run seed 与快照摘要 |

调试构建必须可显示：run seed、逻辑帧号、当前 phase、活动实体数、对象池借出数、最近 20 个 DomainEvent。发布构建不展示该面板。
