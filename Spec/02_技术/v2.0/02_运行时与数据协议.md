# 02｜运行时与数据协议

## 1. 内容文件与校验

内容文件置于 `assets/config/v2/`，必须包含 `manifest.json`、`player.json`、`weapons.json`、`upgrades.json`、`enemies.json`、`waves_normal.json`、`risk_gates.json`、`boss_aegis.json`、`strings_zh_CN.json`。其中 `assets/config/v2/manifest.json` 是仓库根目录 [`素材/manifest.json`](../../../素材/manifest.json) 的构建复制品，不允许手工维护第二份。当前唯一允许的内容版本为 `contentVersion: "2.0.5-release"`；它与构建产物的 SHA-256 一起写入运行记录和回放。加载器必须在进入 `Briefing` 前完成版本、hash 和 ID 交叉引用校验；三者任一不一致均应停留在 Loading 并显示可重试错误。

配置可使用 JSON；数值统一使用 logical px、秒、HP、分数和 0–1 概率。禁止在内容文件中使用毫秒、百分数字符串或隐式单位。所有 ID 为大写字母、数字、`-`/`_`，一经发布不可复用为别的语义。

### 1.1 配置 DTO 的最低字段

| 文件 | 主键 | 必填字段 |
| --- | --- | --- |
| `weapons.json` | `id` | targetingPriority、range、cadence、projectile/hitbox、damage、lifetime、turnRate、area、chain、assetIds；未适用字段必须显式为 null |
| `upgrades.json` | `id` | nameKey、series、maxLevel、weight、prerequisites、excludes、effects[]、iconAssetId；草案全局规则另含 `firstDraftEarliestSecond: 15.0` |
| `player.json` | `id` | spawnPosition、moveSpeed、bodyHitbox、worldBounds、shield/dash/score rules、assets |
| `enemies.json` | `id` | hp、bodyHitbox、contactDamage、moveProfile（路径/振幅/周期/停驻点）、attackProfile（伤害/速度/半径/寿命/预警/命中间隔）、breachDamage、xp、score、spawnWindow、assets |
| `waves_normal.json` | `startSecond` | spawns[]、riskGateId?、clearEnemyBullets、dynamicAdjustmentAllowed |
| `boss_aegis.json` | `id` | hp、body/weakpoint hitbox、entry、phaseThresholds、phases[]（路径/角度/速度/半径/寿命/停顿/召唤坐标）、criticalRule、assets |
| `risk_gates.json` | `id` | availableCondition、effect、cost、timeoutFallback、uiAssetId |
| `strings_zh_CN.json` | key | UTF-8 非空文本；参数以命名占位符表示 |

配置校验必须拒绝：未知 ID、循环前置、互斥卡同时被强制加入、负数 HP/时间、波次重复秒、超过对象预算的单次生成、Boss 缺失安全预警、资产 ID 缺失。

### 1.2 文案调用强制合同

所有玩家可见文本（Widget 文本、HUD 标签、按钮、提示、结算、卡牌标题/描述和 `Semantics` 标签）只能通过 `catalog.text(key, params)` 取得。`strings_zh_CN.json` 是唯一正文来源；缺失 key、参数缺失或多余参数必须在 debug/测试失败，正式版显示受控错误页而不得回退为硬编码文本或裸 key。日志、测试 fixture 与开发调试输出不受本条限制。对 `lib/` 的静态检查必须排除上述非 UI 目录后拒绝新的玩家可见字符串字面量。

## 2. 领域模型和实体协议

### 2.1 必须存在的值对象

| 类型 | 最低字段 | 不变量 |
| --- | --- | --- |
| `EntityId` | kind + monotonic sequence | 一局内唯一，不复用 |
| `Vec2` | x、y | 不含屏幕/Widget 坐标 |
| `Bounds` | center、halfWidth、halfHeight | 尺寸大于 0 |
| `Health` | current、max | `0 ≤ current ≤ max` |
| `Timer` | remaining、period | 逻辑秒；冻结状态不递减 |
| `ModifierStack` | sourceId、operation、value、priority | 同 sourceId 更新而非重复叠加 |
| `RunMetrics` | hpDamage15s、lastDamageAt、kills、maxCombo | 只由 Domain 更新 |
| `DashState` | charges、maxCharges、rechargeTimers、direction、remainingDistance、invulnerable | 每层独立充能；方向在启动时锁定 |

### 2.2 碰撞层与命中闸门

| Layer | 可碰撞对象 | 产出 |
| --- | --- | --- |
| PlayerBody | EnemyBody、EnemyProjectile、Hazard | 玩家伤害意图 |
| PlayerProjectile | EnemyBody、BossWeakpoint | 敌方伤害意图；每投射物-目标对仅一次 |
| PlayerArea | EnemyBody | 导弹/电弧范围伤害；按命中表限频 |
| EnemyProjectile | PlayerBody | 玩家伤害意图；同源 0.25 s 闸门 |
| Hazard | PlayerBody | 每 0.25 s 最多一次伤害 |
| Pickup | PlayerBody | 资源/回复事件；领取一次 |

越界检测不走碰撞系统：`EnemySystem` 在更新位置后检查实体中心 `y > 1140`，生成 `EnemyBreached`，随后由 `DamageSystem` 生成穿透护盾的 HP 伤害并在本步提交移除。该事件必须在常规死亡奖励之前处理，确保突破敌人绝不掉经验/得分。

Broad phase 使用均匀网格或等价空间索引；不得以所有实体两两遍历。碰撞输出为 `DamageIntent`，字段至少为：sourceId、targetId、damageType、rawDamage、frameIndex、hitKey、isCritical。`hitKey` 用于去重，`DamageSystem` 是唯一可更改 HP 的系统。

## 3. 事件协议

事件必须不可变、有 `runId`、`frameIndex`、递增 `eventIndex`。同一帧排序以系统顺序再以实体 ID 排序，确保回放一致。

| 事件 | 必填负载 | 消费者 |
| --- | --- | --- |
| `PlayerDamaged` | sourceType、shieldDamage、hpDamage、direction（8 向枚举）、hpAfter、shieldAfter、hpRatio、shieldRatio | HUD、音频、VFX、指标 |
| `PlayerVitalStateChanged` | hp、hpMax、shield、shieldMax、hpRatio、shieldRatio、cause | HUD、低血/低盾音画；仅数值或阈值状态实际变化时发出 |
| `RunStarted` | seed、prngAlgorithm、contentVersion | 回放、调试、测试 |
| `EnemySpawned` / `EnemyDestroyed` | entityId、enemyId、position、isElite；`EnemySpawned` 的精英另带 `affixId`（`AFFIX-ACCEL`/`AFFIX-SHIELD`/`AFFIX-BARRAGE`） | Flame、Director、音频、奖励 |
| `EnemyBreached` | entityId、enemyId、isElite、breachHpDamage、position | HUD、音频、DamageSystem、测试 |
| `WeaponFired` / `WeaponHit` | weaponId、sourceId、targetId、critical；`WeaponHit` 另含 targetKind、targetEnemyId? | Flame、音频、VFX |
| `WeaponSustainStarted` / `WeaponSustainStopped` | weaponId、sourceId、targetId? | Flame、音频、VFX；持续武器只能用这对事件开关 loop |
| `DashStarted` / `DashEnded` | direction、startPosition、durationSeconds / endPosition、reason | Flame、音频、VFX |
| `DashStateChanged` | charges、maxCharges、availability（ready/cooldown/disabled） | HUD、音频、VFX |
| `EnemyAttackTelegraphed` / `EnemyAttackFired` | entityId、enemyId、attackId、origin、aimTarget、shape、telegraphSeconds；Fired 另带已锁定的执行位置 | Flame、音频、VFX |
| `EnemyDamaged` / `EnemyVitalStateChanged` | entityId、enemyId、hpAfter、hpRatio、critical? / entityId、enemyId、hpRatio | Flame、音频、VFX |
| `EnemyDefenseStateChanged` | entityId、enemyId、frontShieldActive、facingRadians | Flame、VFX；护盾朝向由 facingRadians 旋转，不重算碰撞 |
| `BossAttackTelegraphed` / `BossAttackFired` | attackId、phase、position、geometryId | Flame、音频、VFX |
| `BossAttackEnded` | attackId、phase、reason | Flame、音频、VFX |
| `BossCriticalReached` | bossHp、hpRatio | HUD、VFX、音频 |
| `WaveSpawnResolved` | startSecond、baseSpawns、resolvedSpawns、adjustmentReason | 调试、回放、测试 |
| `UpgradeDraftOpened` / `UpgradeSelected` | candidateIds、selectedId、levels | UI、回放、存档摘要 |
| `RiskGateOpened` / `RiskSelected` | gateIndex、optionId、wasTimeout | UI、回放 |
| `RiskOptionStateChanged` | optionId、state（safe/risk/locked）、lockReason? | UI；每个选项状态变化时发出 |
| `UiControlStateChanged` | controlId、state（pressed/focus/disabled） | Flutter UI；仅表现层事件，不写入 Domain 回放 |
| `BossPhaseChanged` / `BossDefeated` | phase、bossHp | HUD、VFX、音频 |
| `PickupHeal` / `PickupShield` / `DashReady` | source、amountOrCharges、before、after | HUD、VFX、音频、测试 |
| `PhaseChanged` | from、to、reason | UI、生命周期测试 |
| `RunEnded` | result、duration、score、seed、buildSummary、bossHpRatio、resultTier | Result、记录、测试 |

Audio 和 VFX 只能消费事件，不能反向改变 Domain。事件最多保留最近 256 条用于调试；正式回放测试可写入专用 recorder。

### 3.1 素材路由的补充强制合同（v2.0.5）

`attackId` 是稳定枚举，禁止客户端、美术配置或测试用字符串猜测：`scout_shot`、`wing_shot`、`sniper_line`、`bomber_drop`、`shield_shot`、`boss_fan`、`boss_charge`、`boss_ring`、`boss_summon`、`boss_laser`。每一个 `EnemyAttack*` 必须同时携带 `enemyId` 与 `attackId`；每一个 `BossAttack*` 必须携带 `attackId`。素材清单中的攻击相关 binding 必须精确匹配它们，不允许空 `when`。

#### 3.2 强制预警攻击与轰炸危险区的时序合同（F-36 / F-38 批复）

强制预警集合为 `sniper_line`、`bomber_drop`、`boss_fan`、`boss_charge`、`boss_ring`、
`boss_laser`。其中每一招在 `telegraphSeconds > 0` 时均须在 t=0 发相应
`EnemyAttackTelegraphed` 或 `BossAttackTelegraphed`，并建立不可变待执行攻击；
在 `startedAt + telegraphSeconds` 前不得发 Fired、生成伤害实体或结算伤害。到期同一步才发
Fired 并生成实体；对应事件必须携带该招式 t=0 的 `origin`、`aimTarget`、`shape`，
并写入不可变待执行攻击。
预警期间源敌机/Boss 被移除、风险门开启、胜利锁定、重开或非 Playing 状态，待执行攻击必须
取消/冻结且不得残留。渲染快照以独立不可变 `TelegraphView` 公开预警，禁止将其折叠为
`EntityView` 或由表现层猜测目标。

`sniper_line`、`boss_charge`、`boss_laser` 的 origin/aimTarget 均在 t=0 锁定，线形预警沿
该锁定轴裁切到逻辑世界边界；`boss_charge` 采用 `GFX-WARN-CHARGE`，`boss_laser` 采用
`GFX-WARN-LASER`，`GFX-WARN-LINE` 仅能用于 Sniper。`boss_fan` 固定使用
`GFX-WARN-CONE`，`boss_ring` 固定使用 `GFX-WARN-CIRCLE`。上述 Asset ID 必须由配置于
t=0 一并锁定到 `TelegraphView.assetId`，表现层不得猜测。
`bomber_drop` 的落点固定为 t=0 的 origin；预警 0.40 s 后创建半径 90 的 ACTIVE
危险区，持续 2.2 s、每 0.25 s 每目标至多造成 8 点伤害。预警由 TelegraphView 负责，
故 ACTIVE Hazard 的 warningSeconds 为 0，不能重复预警。预警与危险区均处于背景之上、
实体之下；只允许使用 manifest 绑定的正式素材，不得用 Canvas 几何替代资源。
UI-COLORBLIND-PATTERN-DANGER 是屏幕空间危险/濒危标记，禁止整张覆盖世界空间的圆形
Bomber 危险区；Bomber 的正式 WARN/ACTIVE 圆环、十字和圆内纹理承担其非颜色识别维度。

状态阈值以事件完成结算后的 `*After/*Ratio` 为准：HP 为 `>30% normal`、`(10%,30%] low`、`≤10% critical`；护盾为 `>25% normal`、`(10%,25%] low`、`≤10% critical`。`PlayerDamaged` 的 120 ms `hit` 仅为临时表现，结束后必须立刻根据最后一份 `PlayerVitalStateChanged` 重取 normal/low/critical，不能停留在 hit。敌机 `hit` 同样固定 120 ms；敌机 `critical` 为 HP ≤25% 的持久状态。`GFX-EN-SHIELD` 的 `frontShield` 与 `body` 由 `EnemyDefenseStateChanged` 互斥切换，且素材随 `facingRadians` 旋转。

`UI-RESULT-MEDAL` 的 `resultTier` 算法固定如下，避免结算素材无来源：胜利为 `gold`；失败但曾进入 Boss P3（`bossHpRatio < 0.35`）为 `silver`；其余失败为 `bronze`；**不产生 `none`**。优先级依次为 gold > silver > bronze。该值必须在写入 `RunEnded` 前计算，且重放中可复现。

精英表现必须从同一条 `EnemySpawned` 的 `isElite=true + affixId` 精确路由：`AFFIX-ACCEL` → `GFX-ELITE-AURA-ACCEL` + `UI-ELITE-AFFIX-ACCEL`，`AFFIX-SHIELD` → `...SHIELD`，`AFFIX-BARRAGE` → `...BARRAGE`；三种精英均另加载 `UI-ELITE-NAMEPLATE`。名称条只提供底板，敌种名/词缀名使用 catalog key 绘制，不得把文字烘焙进图。色弱图案是固定叠层而非可选主题：危险/濒危使用 `UI-COLORBLIND-PATTERN-DANGER`，奖励/补给使用 `...REWARD`，草案稀有度使用 `...RARITY`。

## 4. 输入协议

每个逻辑步只接受一个不可变 `InputFrame`：`moveX (-1..1)`、`moveY (-1..1)`、`dashPressed`、`pausePressed`、`choiceIndex?`、`pointerActive`。移动向量归一化，键盘对角速度不得更快。边沿字段仅在按下当步为 true；失焦、页面隐藏、状态离开 Playing 时清空所有持续和边沿输入。`DashState` 按产品基线锁定启动方向、360 px 距离和 0.22 s 无敌；不得把每帧输入变化应用到已启动冲刺。

触摸映射：左半屏主指针决定移动目标，释放后速度在 0.08 秒内线性归零；右下冲刺按钮只生成 `dashPressed`；所有 UI 区域优先吞掉指针，不能同时驱动战斗。键盘 Space 与 Shift 都映射 Dash，但同一逻辑步只触发一次。

## 5. 随机、升级与 Director 实现要求

- 选择可复现 PRNG（例如 PCG32/Xoshiro 系列），将算法名和 seed 写入 `RunStarted`；禁止依赖 Dart 默认 Random 的跨版本序列。
- 抽卡先检查累计经验是否达到阈值；第 1 次草案还必须满足 `effectiveCombatSeconds ≥ 15.0`。之后按产品基线完成过滤和保证卡，再从按权重展开的候选集中无放回选择；候选不足 3 时，以未满级通用卡补足，仍不足则配置错误。
- 波次表按 `startSecond` 触发一次。Director 的动态调整只能修改带 `dynamicAdjustmentAllowed=true` 波次中的 Scout/Wing 数量；“升级数”是已选卡次数，最小阈值和同批减员优先级严格使用产品基线 §6，且将调整结果写入 `WaveSpawnResolved` 调试事件。
- 风险门、精英词缀、Boss 阶段不允许由 Director 修改。

## 6. 存档和设置协议

本地存档只存产品基线列出的 key。文件/SharedPreferences schema 带 `schemaVersion=2`；未知字段保留，旧版本缺字段写入默认值，未来高版本 schema 不可写回覆盖。读写失败返回默认内存值并生成非阻塞日志。

设置修改应立即生效并异步持久化：音乐/SFX 影响对应总线；`reduceMotion` 降低非关键信息动画但不关闭预警；触感在支持的原生移动端默认开、Web/macOS 默认关。`HapticPort` 只允许消费 `PlayerDamaged(hpDamage>0)` 的 medium impact、`RiskSelected` 的 light impact、`BossDefeated` 的 success/heavy pattern；护盾受击、普通击杀、射击及不支持平台均不得产生触感。记录只在 `RunEnded` 后写入，分数更高才更新 highScore，通关用时更短才更新 bestClearSeconds。

## 7. 渲染、资源与音频协议

| 层级（后到前） | 内容 | 约束 |
| --- | --- | --- |
| 0–1 | 深空背景/远景 | 可降级，不参与碰撞 |
| 2 | 地面危险预警 | 必须在实体底层之上 |
| 3 | 敌人/玩家/投射物 | 战斗可读性优先 |
| 4 | 命中/爆炸/残影 | 可按预算合并 |
| 5 | Boss 核心、关键预警 | 不得被普通特效遮挡 |
| 6 | Flutter HUD/对话框 | 永远在 World 之上 |

资源用 `AssetId` 查表，不允许散落的字符串路径。图形状态、`DomainEvent → renderState/cueId`、回退资源及音频并发的唯一映射见 [v2.0 素材清单与制作规范](../../03_素材/Warship_v2.0素材清单与制作规范.md) 第 1.1、5.1 节；`AssetLoader` 必须在首次播放/渲染前将 `eventBindings` 解析为不可变表，且只按 `event + when` 条件匹配，禁止仅凭 `triggerEvents`、文件名或显示文本选资源。Loading 阶段预载 manifest 中 `loadGroup=firstRun` 的图形与音频；`boss` 在 Boss 倒计时前预载，`lazy` 可惰性加载但不得造成攻击缺贴图。音频采用 Music/SFX/UI/Warning 四总线，Warning 优先；高频 `WeaponFired`、`WeaponHit` 按 80 ms 合并，同 cue 最大并发由素材元数据指定。暂停停止或挂起持续音，恢复不得重复叠层。发布构建不得实际走到 GFX/UI 回退或必需 cue 的静默回退；若走到，记录 Asset ID 并使资源验收失败。

### 7.1 Boss 胜利原子收口

`BossDefeated` 在 `DamageSystem` 确认 HP=0 的同一逻辑步内执行，顺序固定为：①结算该次 Boss 击杀的分数/经验；②写入不可逆 `victoryLocked=true`；③移除敌人、敌方投射物与危险区并取消其 timer；④清空尚未提交的玩家受伤 `DamageIntent`，关闭碰撞与所有伤害 tick；⑤仅允许胜利表现/音频事件，最后发 `RunEnded`。`victoryLocked` 后，`DamageSystem` 必须拒绝所有以玩家为 target 的 intent，`EnemySystem`/`DirectorSystem` 不得产生伤害源，且禁止 `PlayerDamaged`、死亡和受击 cue。不得仅清“在飞子弹”。

## 8. 内容导入与迁移检查

开发开始前应提供 `content_validate` 开发命令或同等测试：加载全部 JSON、校验 Schema、引用、资产清单、波次数量与对象预算。CI 必须运行它。任何产品数值修改必须同时更新 content 版本、变更说明和对应测试 fixture；不得改动 Domain 代码来实现单一内容特例。
