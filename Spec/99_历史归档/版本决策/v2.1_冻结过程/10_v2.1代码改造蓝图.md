# v2.1 代码改造蓝图（工程实施冻结）

> 状态：**实施冻结稿。** 本文把已确认的 v2.1 需求落到当前仓库的精确文件、类、方法、数据合同与旧路径退出规则。一线研发只需同时执行 09 一线实施冻结表、08 素材清单与本文，无需再向技术架构师确认“改在哪里、怎么改”。

> **边界：** 本文仅描述 v2.1 开发分支；不得修改现行 v2.0 生效文档或素材。不得用 Canvas 几何、旧占位图、临时路径或未经审核的素材代替 08 中的真实资源。

## 1. 完成定义与架构边界

标准 XP 强化不再进入 GamePhase.upgradeDraft。强化、敌人、玩家操作、射击与逻辑时钟全程不中断；风险门仍是唯一保留的玩家选择覆盖层。对局结果只能由 GameRuntime 产生且仅一次的 RunEnded 驱动，App 层不得通过玩家是否死亡、HUD 倒数或墙上时钟猜测胜负。

~~~text
真实 v2.1 config / manifest / 素材
                 │（版本、hash、ID、帧区间校验）
          V2Bootstrap / ContentCatalog
                 │
GameRuntime ─ DomainEvent ─ AudioDirector / VisualEffects
     │               │
     ├ AutoUpgrade / WeaponStyle / ThreatSnapshot
     └ RenderSnapshot（唯一的 Core → Presentation 合同）
                         │
             WarshipV2Game + V2RunScreen
                         │
          非阻断提示 / 目标 HUD / 结果奖章
~~~

硬约束：

1. Domain/Core 不依赖 Flutter、Flame、图片路径或音频路径；只保存规则、稳定 ID、不可变事件和快照。
2. Presentation 不修改 GameRuntime，不自行计算胜利、抽卡或目标文案。
3. 资源只从一份 assets/config/v2/manifest.json 的 eventBindings + when 解析；不得新建第二份运行时 manifest，也不得按文件名猜资源。
4. 所有新增 public 类型、事件、状态字段、时序、取消分支必须有简体中文“为什么”注释，写明单位、所有权和取消条件。命名采用 Dart lowerCamelCase、类型 UpperCamelCase、稳定内容 ID 使用 UP-/GFX-/UI-/SFX- 前缀。

## 2. B0：版本、配置和资源装配（先完成）

### 2.1 单一版本入口

当前 AssetManifest.requiredContentVersion 固定为 2.0.6-material-repair，V2Bootstrap 也固定读取 assets/config/v2。以下四项必须在同一提交完成，不能只改 JSON：

| 文件 | 精确改动 | 必过断言 |
| --- | --- | --- |
| lib/game/content/asset_manifest.dart | 去除作为默认值的硬编码 requiredContentVersion；parse 的 expectedVersion 改为由 bootstrap 显式传入。保留版本不符即 Loading 失败。 | manifest=2.1.0-neon-flow 成功；任一 v2.0 文件混入则失败。 |
| lib/game/content/content_catalog.dart | ContentCatalog.load 接收并使用同一 expectedVersion 校验 8 份内容文件；不得回落至 v2.0 默认常量。 | 错误信息含不一致文件名。 |
| lib/app/v2_bootstrap.dart | 新增唯一常量 kActiveContentVersion = 2.1.0-neon-flow；传给 AssetManifest.parse 与 ContentCatalog.load。 | 代码中没有第二个 v2.1 版本字面量。 |
| assets/config/v2/ 全部 JSON 与 manifest | 在 v2.1 分支同步升为同一 contentVersion。v2.0 发布物由 tag/发布分支保留，不复制第二份 manifest。 | 内容/manifest 交叉引用单测通过。 |

kConfigRoot 继续为 assets/config/v2。Spec/04_下一版本规划/v2.1/素材 是交付源，不是运行时目录；构建脚本必须复制/打包审核通过的文件到 manifest 路径，并复核 SHA-256。

### 2.2 配置变更清单

| 文件 | 动作 | 必填项 |
| --- | --- | --- |
| upgrades.json | 原 16 张卡原样保留；追加 5 张 UP-WSTYLE-*；保留 XP 阈值和 maxDrafts=6。删除或不再消费仅服务三选一卡 UI 的 draftSize/guaranteed 逻辑。 | 09 §2、§3 的互斥、效果、countsAsDamage、中文 key、资源 ID。 |

| strings_zh_CN.json | 增加 09 §3.1 全部 key，且补齐 objective.survive、objective.bossIncoming、objective.defeatBoss、objective.timeLimit。 | UI 不显示 key、UP- ID 或裸剩余秒数。 |
| manifest.json | 新增 08 的 21 个图形/UI ID 与 12 个 SFX ID，每个 sheet 子图各自配置 frameRect。 | 真实 runtime path、SHA、loadGroup、eventBindings、maxVoices、minRetriggerMs。 |

新增资源路由不可省略：

| 事件 | when | 资源 |
| --- | --- | --- |
| AutoUpgradeGranted | 任意 | UI-V21-UPGRADE-NOTICE + SFX-V21-UPGRADE-GAIN |
| WeaponHit | weaponStyleId=prism/arc/plasma/needle/missile | 对应 GFX-V21-WPN-*-IMPACT + SFX-V21-WPN-*-IMPACT |

| PlayerVitalStateChanged | hpVisualState=low/critical | GFX-V21-PLAYER-LOW / GFX-V21-PLAYER-CRITICAL |

manifest 只允许等值 when 条件，因此 conditionalParamsOf 必须输出稳定枚举 damageLayer=shield 或 hp，不得隐式扩展 schema 做数值表达式比较。

## 3. B1：Core / Domain 的逐文件改造

### 3.1 lib/game/core/domain_event.dart

新增不可变事件，并在同一提交补生产者、Audio/Visual 消费者、单元测试：

~~~dart
AutoUpgradeGranted({
  required int grantOrdinal,
  required String cardId,
  required int newLevel,
  String? weaponStyleId,
})
SectorClearStarted({required double confirmSeconds})
SectorClearCancelled({required String reason})
SectorClearConfirmed()
~~~

WeaponFired 与 WeaponHit 增加 nullable weaponStyleId；旧主炮和副武器传 null，五种主弹道传稳定 style ID。RunEnded 增加 reason，值只能为 bossDefeated、sectorCleared、playerDead、timeLimit；保留 result 和 resultTier，禁止 App 层重算。

### 3.2 lib/game/domain/upgrade_system.dart

1. UpgradeState 的 draftCount 迁移为 grantCount；新增 mainWeaponStyleId、consecutiveGrantsWithoutDamage。reset/dispose、回放和调试输出必须同步覆盖。
2. isDraftDue 改名 isAutoGrantDue。generateDraft 改为 grantAutomatic，返回单张 AutoUpgradeGrant；先按 09 §2.2 选 1 个 ID，再且仅一次 applyCard。
3. 强制池或候选池为空时抛 StateError，错误包含 grantOrdinal 与可用 ID；不得静默跳过、不得“安全回退”到没有强化。
4. 标准 XP 路径不再生产 DraftOffer、UpgradeDraftOpened 或 UpgradeSelected。风险门仍可按既有流程选择，并用同一单卡授予 API 发放其稀有奖励。

### 3.3 lib/game/core/game_runtime.dart

1. _stepOnce 第 10 步将 _checkDraftDue 替换为 _checkAutoGrantDue；完成 apply、_recomputeModifiers、AutoUpgradeGranted、toast 状态更新，全程不变更 phase。
2. 删除 advance 中 GamePhase.upgradeDraft 的输入分支，删除 currentOffer、selectDraftCard 与 snapshot 的 upgradeDraft 生产路径。若短期保留枚举，必须不可达、标 deprecated，并有静态测试。
3. _fireWeapons 创建 Projectile 时保存 style ID、projectileAssetId、impactAssetId、已应用倍率后的 damage/speed/radius、pierce/bounce、homing 锁定信息。
4. snapshot 对玩家投射物的 EntityView.assetId 必须取 Projectile.projectileAssetId，不能由表现层按武器名猜。
5. 新增私有 SectorClearState(inactive/confirming/confirmed)、confirmStartedAtSeconds、terminalResult；每局 reset/dispose 时清零。

### 3.4 lib/game/domain/weapon_system.dart

新增不可变 WeaponStyleSpec，从 weapons.json 解析。PulseWeapon 持有 nullable activeStyle；无 style 时 v2.0 行为字节级等价。每次 FiringRequest 必带：

~~~text
weaponStyleId / projectileAssetId / impactAssetId
damage、speed、radius（已应用倍率）
pierceRemaining / bounceRemaining / homingTargetId
~~~

碰撞规则严格为：

- Prism：命中后还能命中 1 个不同目标。
- Arc：首命中后在 360 logical px 内以距离、EntityId 选一个未命中合法目标；无候选即销毁。
- Plasma：首命中即销毁；伤害半径由显式 impactDamageRadius 配置，绝不从 96px 图片尺寸推断。
- Needle：命中后还能命中 2 个不同目标。
- Missile：每逻辑步向初次锁定的最近合法目标转向；目标无效时仅重新选一次，不消耗随机；无目标直线飞行。

Projectile 生命周期保存已命中的 EntityId 集合。弹跳、穿透、追踪永不命中玩家、拾取物或已移除实体。

## 4. B3：清场胜利、快照与 App 层

### 4.1 GameRuntime 的唯一胜负来源

在每逻辑步 _commitPending 后构建唯一 ThreatSnapshot：

~~~text
directorCompleted
&& !hasFutureBossPlan
&& enemies.isEmpty
&& enemyProjectiles.isEmpty
&& hazards.isEmpty
&& pendingAttacks.isEmpty
&& !bossAlive
~~~

- 第一次成立：状态转 confirming，发 SectorClearStarted(confirmSeconds: 0.8)，不清敌、不冻结。
- 0.8 秒内任一条件失效：状态回 inactive，发 SectorClearCancelled(reason)，不可留存倒数。
- 连续 0.8 秒成立：发 SectorClearConfirmed，调用唯一 _endRun(victory, sectorCleared)。
- Boss 击败也调用 _endRun(victory, bossDefeated)。该方法以 runEnded guard 保证仅一次，先原子停止敌方伤害源/生成，再发 RunEnded。
- player.json 的 190 秒到达且未结束：调用 _endRun(defeat, timeLimit)。玩家死亡调用 _endRun(defeat, playerDead)。**存活到 190 秒绝不等于胜利。**

### 4.2 lib/app/v2_app_flow.dart

_checkRunOver 仅消费 runtime.terminalResult 或本帧唯一 RunEnded，把 result、resultTier、durationSeconds 传入 _onRunFinished。删除当前以 player.health.isDead 与 combatSeconds >= 190 推断结果的代码；_onRunFinished 不得重新计算奖章。build 的 GamePhase.upgradeDraft 路由删除或标为不可达，riskGate 保留。

### 4.3 lib/game/core/render_snapshot.dart 与 snapshot()

删除 RenderSnapshot.upgradeDraft，新增：

~~~text
HudView.objectiveKey: String
HudView.objectiveArgs: Map<String, Object?>
HudView.isSectorClearConfirming: bool
HudView.autoUpgradeToast: AutoUpgradeToastView?

AutoUpgradeToastView{
  grantOrdinal, cardId, nameKey, descKey, newLevel,
  styleId?, startedAtSeconds, expiresAtSeconds
}
~~~

objectiveKey 仅由 Runtime 映射 09 §4 的状态，Widget 只能 catalog.text(key,args)。Toast 在 1.2 秒内是快照状态；异常同帧多发按 grantOrdinal 排队，不丢事件。暂停时 toast 与清场确认均冻结。

## 5. B4：表现、音频和 UI 的逐文件改造

### 5.1 lib/game/presentation/visual_effects.dart / warship_v2_game.dart

现有 VisualRouter 只适合单张状态贴图，不能承载 v2.1 sheet 动画；绝不能把受击 sheet 赋给 player.assetId。新增 SpriteSequenceEffect，由 VisualEffects 管理：

- 事件型：盾受击、HP 受击、敌人击毁、主弹道命中。以 StampedEvent.frameIndex + 逻辑帧率计算开始时间，暂停和回放稳定。
- 状态型：低血/濒危。由 HudView.hpVisualState 创建或撤销唯一实例，恢复正常立即撤销；不能仅靠 PlayerDamaged 的临时路由。
- VisualAssetCache 按 08 frameRect 取帧；解码/帧表失败在开发和测试失败并记录 Asset ID，Release 素材验收失败。
- 09 §5 的 blend、尺寸、锚点、时长、并发和 reduceMotion 是逐项合同。effects.step 仅在 playing 推进；暂停只画当前帧。

渲染顺序固定：背景 → 预警/危险区 → 实体 → 机体状态叠层 → 事件命中特效 → 伤害数字/拾取物 → HUD。任何新增 drawImageRect 都必须登记 drawnAssetMaxRadius/drawHistory，保持既有诊断和 draw_record_coverage_test 有效。

### 5.2 lib/app/v2_run_screen.dart

1. 删除 DraftView、_DraftOverlay、_selectCard，只保留风险门选择。
2. _HudOverlay 接收 autoUpgradeToast，在 09 §2.3 右上安全区用 IgnorePointer(ignoring:true) 绘制；加 Semantics(label: catalog.text(toast.upgradeAria,args))。
3. _TimerPanel 改名 _ObjectivePanel；只渲染 hud.objectiveKey/objectiveArgs，禁止再渲染 190-combatSeconds 或裸数字。
4. 结果页直接接收 Runtime 的 resultTier，按 tier 使用独立 UI/SFX 和 09 §5.2 时间轴；不可用同一个四边形资源改颜色/文字冒充奖章。
5. _onSnapshot 的差异判断增加 objective、toast、HP 状态和 result，避免提示/动画因为不 setState 而失效。

### 5.3 lib/game/infrastructure/audio_director.dart

conditionalParamsOf 新增 AutoUpgradeGranted、SectorClearStarted、RunEnded.resultTier、WeaponHit.weaponStyleId 和 PlayerDamaged.damageLayer。五形态命中不得被 _audioWeaponId(WPN-PULSE) 错路由到旧 pulse cue。新 cue 无 manifest 匹配时测试失败；运行时诊断记录事件、条件和 Asset ID，不能静默播放旧音效。
