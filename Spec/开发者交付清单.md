### 3.1 正式资源硬性规则

- 当前唯一接受的 `contentVersion` 为 `2.0.6-material-repair`；v2.0.7 是素材审计/补丁
  文件版本，不得改动运行时版本常量。
- `EnemyAttackTelegraphed` / `EnemyAttackFired` 必须以 `enemyId + attackId` 精确路由；Boss 攻击必须以 `attackId` 精确路由。
- 不得硬编码资源路径、由文件名猜测资源或创建第二份 manifest。
- 不得将根目录 `assets/images/`、`assets/audio/` 的升级前资源接入 v2.0；它们只服务于现有基线运行和迁移对照。
- 构建时将 `素材/manifest.json` 及 manifest 引用的资源复制到应用的 `assets/config/v2/` 和运行时资源目录；详见 [运行时与数据协议](02_技术/v2.0/02_运行时与数据协议.md)。

### 3.2 v2.0.6 必做素材同步（敌机与音频）

本节是本次资源修复后，研发必须执行的**代码/构建接入动作**；不要求、也不授权研发改动
任何源素材。

1. 将 `素材/manifest.json` 同步覆盖 `assets/config/v2/manifest.json`，并同步 manifest
   所列图形/音频运行时文件至 `assets/images/v2/`、`assets/audio/v2/`。提交前断言应用内 manifest 的 `contentVersion` 为
   `2.0.6-material-repair`。
2. 将五类敌机显示统一收敛到 manifest 状态解析：正常为 `idle`（Shield 为 `body`），
   受击为 `hit`，濒危为 `critical`，击毁为 `destroy`；仅 Sniper 使用 `charge`，
   仅 Bomber 使用 `drop`，仅 Shield 正面减伤使用 `frontShield`。
3. 删除或禁用任何把敌机正常态渲染为圆点、三角形、通用盾牌或 `GFX-FALLBACK-SILHOUETTE`
   的代码分支。加载失败必须进入错误日志/验收失败路径，不能静默伪装为正常游戏画面。
4. 音频播放只消费 `cueId`。禁止将不同 `cueId` 人为映射到同一个文件、同一个预加载
   buffer 或通用占位 beep。
5. 合并前必须执行第 6 节四个素材门禁，并补充 macOS/Web Release 截图：五类敌机可仅凭
   剪影区分，Sniper 蓄力、Bomber 投放、Shield 正面护盾可被逐一观察到。

## 6. 开发前与发布前检查命令

在仓库根目录运行：

```bash
flutter analyze
flutter test
python3 素材/元数据/validate_release_manifest.py
python3 素材/元数据/validate_visual_state_assets.py
python3 素材/元数据/validate_audio_mix.py
python3 素材/元数据/validate_web_load_budget.py
```

预期结果：Flutter 静态分析无问题、自动化测试全部通过，且素材校验分别确认资源完整性、图形状态、音频混音和 Web 首屏预算。

### 6.1 后续版本新增的 Code Review 门禁

除上述自动化命令外，每个功能合入与每个发布候选均须完成技术测试计划的 CR-01～CR-05：架构边界、命名、关键注释、测试质量和变更追溯。项目负责人在最终验收时独立复核；“已有测试通过”不能替代代码评审。
