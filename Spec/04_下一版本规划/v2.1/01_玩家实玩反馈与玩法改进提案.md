# 《Warship：霓虹最后防线》v2.1 玩家实玩反馈与玩法改进提案

| 项目 | 内容 |
| --- | --- |
| 文档状态 | **讨论稿，待产品确认；不是当前实现依据** |
| 来源 | 负责人实际游玩反馈，2026-10-16 |
| 目标 | 保持 3 分钟、低学习成本、无登录的快节奏体验；减少打断和无效等待，增强战斗反馈、武器辨识与结算满足感 |
| 不在本稿范围 | 代码实现、素材制作、技术选型、数值最终平衡、登录/联网/PVP |

## 1. 本次问题归纳

| 实玩问题 | 玩家感受 | v2.1 设计方向 |
| --- | --- | --- |
| 受击、濒危等效果是静态图层停留后消失 | “有反馈，但不酷、不现代” | 状态图层改为有明确时间曲线的动效系统 |
| 升级三选一强制停下 | 战斗流被频繁打断 | 默认自动强化、不中断战斗；强化效果用短提示与战机变化表达 |
| 屏幕无敌后仍要等倒计时结束 | 不清楚目标，产生无意义等待 | 建立“战场已清空即立即结算”的明确结束规则 |
| 子弹长期是相同双线 | 审美疲劳、强化成长不直观 | 强化同时改变武器行为与可识别弹道风格 |
| 金银铜奖牌同形同图、像矩形底板 | 通关奖励缺乏仪式感 | 三档奖章拥有独立形状、材质、动效与结果呈现 |

## 2. v2.1 核心体验原则

1. **不停手**：默认战斗过程中不弹出必须操作的升级选择；玩家注意力留在走位、射击和躲避。
2. **看得见成长**：每次强化至少带来一种立刻可见的变化——弹道、命中、引擎、护盾或战机部件；不能只有隐藏数值变化。
3. **没有空等**：当游戏不再提供可交互威胁时，必须在短暂的胜利确认后立即结算。
4. **动效服务信息**：受击、濒危、强化、命中、击毁和奖章的动效必须强化状态识别，不能遮挡机体、危险区或输入。
5. **确定性不退步**：自动强化与视觉随机性必须受 `run_seed` 控制，以便重放、测试与平衡复现。

## 3. 候选变更 A：战机状态从静态贴图升级为分层动效

### 3.1 目标体验

玩家受击时看到“冲击 → 能量扩散 → 收束”的短促动画，而不是一个静态特效盖在机体上；低血与濒危为持续但呼吸式的危险提示，不遮住战机本体。

### 3.2 规则候选

| 状态 | v2.1 动效要求 | 时长/节奏候选 | 不可违反的可读性约束 |
| --- | --- | --- | --- |
| 护盾受击 | 六边形冲击点从命中方向扩散，环形波纹缩回 | 120–180 ms，最多叠加 2 次 | 仅加亮/透明叠加，机体始终可见 |
| HP 受击 | 白热闪点、碎片/电弧向外短喷，随后淡出 | 180–260 ms；同帧合并 | 不用整张不透明图覆盖机体 |
| 低血 | 引擎间歇失火、琥珀脉冲、机体边缘轻微闪烁 | 1.2 s 呼吸循环 | 不改变碰撞体、速度、射击频率 |
| 濒危 | 在低血基础上增加不规则电弧和较快的呼吸节奏 | 0.65 s 循环 | 不能与敌方危险色/预警混淆 |
| 命中敌人 | 命中点能量火花、短拖尾和方向反馈 | 60–140 ms | 高频命中要合并，避免粒子/音频爆炸 |
| 敌人击毁 | 核心爆裂、外壳碎片、残光消散 | 240–420 ms | 击毁后判定立即关闭；动效不保留伤害 |

### 3.3 素材与交互要求（待确认后进入素材规范）

- 每个上述状态须提供至少 3 帧序列或可参数化的透明分层素材；单帧静态 PNG 停留不再作为正式交付。
- 必须定义锚点、混合方式、帧率/时间曲线、最大并发、低性能降级方案和结束条件。
- `reduceMotion` 只能缩短非关键碎片/缩放，不得取消受击、低血、预警或强化的状态提示。
- 屏幕录制验收须能看出：状态发生、动效过程、结束恢复，且机体轮廓未被遮挡。

## 4. 候选变更 B：自动强化，战斗不停顿

### 4.1 目标体验

经验达到阈值时，系统在同一逻辑步自动授予一项合法强化；战斗、移动、子弹和敌人均不停顿。玩家在侧边获得短提示，并通过弹道/机体实际变化感知成长。

### 4.2 默认流程候选

~~~text
达到强化阈值
  → 过滤满级/互斥/不可用强化
  → 保底与权重规则生成候选池（仍受 run_seed 控制）
  → 自动选定 1 项
  → 同步应用数值与视觉形态
  → 右侧/顶部出现 1.2 秒「强化获得」轻提示
  → 战斗持续，不进入 UpgradeDraft，不冻结逻辑时钟
~~~

| 规则 | 候选定义 |
| --- | --- |
| 自动选择 | 保留现有保底、互斥、最大等级和权重规则；从合法候选中确定性抽取 1 项 |
| 防止重复 | 连续两次不得出现完全相同的强化；若候选不足，允许升级已有系列但须在提示中显示等级变化 |
| 强化提示 | 不遮挡玩家和 Boss；显示图标、中文名称、等级、1 句效果；1.2 秒后收束为 HUD 小图标 |
| 视觉反馈 | 每次强化必须至少改变弹道、命中、引擎、护盾或无人机之一；纯数值强化使用对应短动效说明 |
| 历史记录 | 暂停页/结算页展示本局已获得强化清单，便于理解自动分配结果 |
| 无输入抢占 | 期间键盘、触摸、冲刺、暂停均保持正常；提示不可吞战斗输入 |

### 4.3 待确认问题

本稿建议 v2.1 **默认且仅提供自动强化**，避免再次引入中断式选择。若你希望保留策略深度，可在后续单独讨论“开局选择自动/手动模式”；该模式不在本轮默认范围内。

## 5. 候选变更 C：零敌人空窗立即结算

### 5.1 问题定义

当当前屏幕不再有敌机、敌弹、危险区或待执行攻击，但顶部仍显示倒计时/剩余数量时，玩家无法判断是否应继续等待，造成几十秒无操作价值的空窗。

### 5.2 结算规则候选

**推荐规则：清场胜利。**以下条件同时满足时，进入“扇区已清空”确认，而非继续倒计时：

1. Director 已消费本局最后一个计划波次，且不会再生成任何普通敌人或 Boss；
2. 场上敌人、敌方投射物、危险区、待执行攻击均为 0；
3. 不处于升级、风险门、暂停、加载或已结算状态；
4. 保持 0.8 秒，仅用于播放清场音画，不可被新的生成打断。

0.8 秒结束后立刻进入胜利结算；不得再等待原先的倒计时上限。顶部中间的显示应改为**当前目标**（例如“守门者到达前”“威胁清除中”“守卫已完成”），不得只显示会误导玩家的剩余数字。

### 5.3 与 Boss 的关系

- Boss 路线仍以 Boss HP=0 为最高优先级胜利条件，维持击败后立即原子收口。
- 如果 Director 因内容配置完成而不再计划 Boss，则必须在开局配置校验时报错；不能依赖“无敌后倒计时结束”掩盖配置/流程缺陷。
- 清场胜利不得在 Boss 尚未生成但未来波次仍存在时触发。

## 6. 候选变更 D：强化驱动的弹道形态进化

### 6.1 目标体验

强化不仅“更多伤害”，还让玩家每局获得不同、可读、可听的弹道个性。形态变化必须同时改变视觉与至少一个可测规则参数，避免只是换皮。

### 6.2 武器形态池候选

| 形态 ID（暂定） | 视觉 | 规则变化候选 | 命中效果 |
| --- | --- | --- | --- |
| `STYLE-PRISM` | 青白棱晶短束，命中后分裂光屑 | 2–3 路窄角散射；单发伤害略降 | 棱镜碎光 |
| `STYLE-ARC` | 蓝紫电弧弹，带跳跃尾线 | 命中后向最近目标 1 次弹跳 | 电弧链与电流声 |
| `STYLE-PLASMA` | 橙红等离子团，慢速大核心 | 弹速降低、半径提升、短范围溅射 | 环形热浪 |
| `STYLE-NEEDLE` | 洋红高速针束，细长残影 | 更高弹速、低半径、穿透 1 个目标 | 直线穿孔火花 |
| `STYLE-MISSILE` | 琥珀微型导弹，尾焰明显 | 低频追踪、小范围爆炸 | 小型锁定爆裂 |

### 6.3 生成与平衡边界候选

- 一局可拥有 1 个主弹道形态；后续同系列强化提升该形态，不随机替换造成学习负担。
- 第 1 次自动强化仍保证基础射速成长；第 2–4 次至少获得一次形态或明显的命中特效变化。
- 形态池、权重、互斥、伤害、速度、半径、穿透、爆炸和特效并发均须数据化；同 seed 同输入必须得到同一形态序列。
- 每个形态在高对比、灰阶和 `reduceMotion` 下仍可与敌弹、敌人和危险预警区分。

## 7. 候选变更 E：三档奖章重做

### 7.1 目标体验

结算奖章应该是一次通关的“奖杯”，而不是同一张矩形底图换文字或颜色。Gold、Silver、Bronze 必须在形状、材质、动效和音效上无需阅读文字即可区分。

### 7.2 视觉规则候选

| 档位 | 独立形态 | 材质/色彩 | 入场动效 | 音效/触感候选 |
| --- | --- | --- | --- | --- |
| Gold | 六角徽章 + 展翼星核 | 金色金属、白色高光、细小星尘 | 旋入 → 星核点亮 → 轻微停留 | 上扬三音；支持平台成功触感 |
| Silver | 圆形盾章 + 月弧核心 | 银蓝金属、冷白反射 | 从两侧合拢 → 月弧亮起 | 两音确认 |
| Bronze | 三角/盾形勋章 + 暖色核心 | 铜橙金属、深色压纹 | 上浮 → 核心短亮 → 收束 | 单音确认 |

### 7.3 结算与素材要求

- 沿用当前结果逻辑候选：胜利 Gold；失败但 Boss HP <35% 为 Silver；其余失败 Bronze；不产生 `none`。
- 每档必须有独立 Asset ID、独立源文件与运行时导出；禁止同一个底图通过着色模拟三个档位。
- 每档交付完整动效序列、静态降级态、锚点、时长、透明区、混合方式与音效绑定；结算页必须显示实际 `resultTier` 对应素材。
- 验收用例需逐档截取结果页，验证 Asset ID、可见形状差异、入场动画、中文文案和结果规则一致。

## 8. 建议的 v2.1 最小可玩闭环

建议按“先消除中断和空等，再增强表现与多样性”的顺序交付：

1. 自动强化与侧边获得提示；
2. 清场即时结算与顶部目标文案；
3. 玩家受击/濒危/命中/击毁分层动效；
4. 至少 3 种主弹道形态；
5. Gold/Silver/Bronze 独立奖章与结算动效。

完成上述五项后，玩家一局的体验变化应为：**始终能操作 → 持续看到成长 → 战场结束立刻收束 → 每局弹道有差异 → 结果有奖赏感**。
