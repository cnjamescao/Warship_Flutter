## 1. 已确认范围

### 1.1 自动强化，不中断战斗

1. 取消手动三选一和 `UpgradeDraft` 对战斗的强制冻结。
2. 达到强化阈值时，系统依据合法候选、保底、互斥、等级上限和 `run_seed` 自动选择 1 项强化。
3. 选择后同一逻辑步应用，战机移动、射击、敌人、投射物、危险区和计时均持续推进。
4. 在侧边或顶部安全位置展示 1.2 秒非阻断提示：图标、中文名称、等级和一句效果说明；之后收束为 HUD 强化记录。
5. 自动强化必须让玩家立刻感知变化：弹道、命中、引擎、护盾、无人机或对应短动效至少变化一项。
6. 暂停页和结算页显示本局已获得强化，确保玩家可回看系统随机给予的内容。

### 1.2 清场立即结算，禁止无意义等待

满足以下条件时，进入 0.8 秒“扇区已清空”确认并立即结算胜利：

- Director 已消费所有计划波次，未来不再生成普通敌人或 Boss；
- 敌人、敌方投射物、危险区、待执行攻击均为 0；
- 当前不是加载、暂停、风险门、强化或已结算状态。

Boss 被击败仍为最高优先级胜利条件，维持即时原子收口。若内容配置存在未来 Boss 但未生成，属于配置/流程缺陷，不能以清场胜利掩盖。顶部中间仅显示当前目标或清场状态，不得显示会让玩家空等的剩余数字。

### 1.3 随机强化中的主弹道形态

Prism / Arc / Plasma / Needle / Missile 是首批获准进入强化池的候选形态。它们是“随机给予玩家惊喜”的强化内容，而不是开局选择或固定职业。

| 形态 | 核心可感知变化 |
| --- | --- |
| Prism | 窄角分束、棱晶命中特效 |
| Arc | 跳跃电弧、链式命中反馈 |
| Plasma | 较慢大核心、范围热浪 |
| Needle | 高速细束、穿透火花 |
| Missile | 低频追踪、微型爆裂 |

每种形态必须同时改变可测试的规则参数与独立的视觉/音效；一局只保留一个主形态，后续同系列强化提升该形态，不随机替换。最终权重、数值、互斥与首次出现时机已由本目录 [功能冻结表](Warship_v2.1功能冻结表.md) §2–§3 冻结；研发不得另行猜测或调整。

### 1.4 分层短促战斗动效

整体风格确定为：**霓虹硬科幻、利落短促**。

- 护盾受击、HP 受击、低血、濒危、命中、敌人击毁均须以分层、透明、短时间曲线动效表达；不可再以静态整图停留替代。
- 受击动效必须保留战机本体可见；濒危/低血不改变碰撞、速度与攻击节奏；击毁动效不保留伤害判定。
- 高频事件须有限并发和合并策略；`reduceMotion` 仅降低非关键信息动效，不能取消状态辨识。

### 1.5 独立形态的三档奖章

1. 维持结果规则：胜利 Gold；失败且 Boss HP <35% 为 Silver；其他失败为 Bronze；不产生 `none`。
2. Gold、Silver、Bronze 必须分别使用独立的形状、源文件、运行时 Asset ID、材质、入场动效与音效；禁止同一矩形底图仅换色或换字。
3. 动效采用短促、克制的金属点亮/旋入/收束，不使用夸张街机爆炸。
4. 结算验收须逐档验证实际结果规则、对应素材、形态差异和动效过程。

## 2. 下一步交接要求

在任何代码开始前，研发、UI/TA、音频、QA 需基于本文件分别产出并评审：

| 角色 | 必须产出 |
| --- | --- |
| 技术架构 | 自动强化事件/状态机、清场判定、武器形态数据模型、动效快照与生命周期设计 |
| 平衡/玩法 | 所有形态的数值、权重、出现窗口、互斥、升级上限和固定 seed 样例 |
| UI/TA | 分层序列/程序参数、锚点、混合方式、帧率、最大并发、降级规则、三档奖章源稿与导出 |
| 音频 | 五种形态与三档奖章的 cue、时长、并发、响度与总线规则 |
| QA | 自动强化不中断、清场不空等、形态可辨识、动效结束、奖章差异、确定性和性能验收用例 |
