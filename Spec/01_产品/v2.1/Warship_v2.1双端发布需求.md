# Warship v2.1 Web 与 macOS 双端发布需求

> **状态：当前生效的 [新增 v2.1-Web] 发布需求。** 本文把 Web 从“可编译的未来能力”升级为与 macOS App 同等的正式发行目标。产品玩法、数值、内容版本和真实素材只维护一份；任何一端未达到发布门禁，两个端都不得以“v2.1 正式版”名义单独发布。

## 1. 目标、范围与不变项

| 项 | 决定 |
| --- | --- |
| 正式平台 | macOS 原生 App、桌面浏览器 Web；同一 release train 一起发布 |
| Web 首发浏览器 | Chrome、Safari、Edge 的当前与上一大版本；桌面浏览器优先 |
| 不在首发范围 | 移动网页适配、账号、云存档、联机、支付、服务器玩法逻辑 |
| 玩法一致性 | 同一 `contentVersion`、相同 seed/输入的 Domain 结果一致；不能为 Web 另开规则分支 |
| 本地数据 | 两端都仅保存本机设置和记录；Web 使用浏览器本地存储，清站点数据等同清空本地记录 |
| 手势与声音 | Web 在首次有效玩家手势后才可启动音频；手势前不能阻断开局或显示错误 |

Web 首发仍以键盘/鼠标桌面体验为准：WASD/方向键移动，Space/Shift 冲刺或射击，Esc 暂停。浏览器页面的可见区域小于 `1024×640 CSS px` 时，不得开始对局，须显示“请扩大浏览器窗口或使用桌面设备”的静态提示；不以压缩 HUD、裁掉战场或改变逻辑世界来勉强运行。

## 2. 玩家可见的 Web 行为

1. 玩家访问静态站点后，先看到不伪造百分比的加载态；首帧成功即进入 App。网络/资源失败或 20 秒超时，显示可重试，而不是白屏或无限转圈。
2. 首次点击开始、战场点击或有效按键是“音频解锁手势”。手势成功后，若音乐设置开启，BGM 在下一逻辑步开始；解锁失败仅保持无声并保留设置入口，绝不暂停、重置或中断本局。
3. 切换标签页、最小化、窗口失焦、设备锁屏会自动进入既有暂停；恢复后由玩家明确点击“继续”或按 Esc 恢复，不得在后台累积伤害、时间或随机数。
4. 浏览器缩放、窗口尺寸变化和 4:3 / 16:9 / 21:9 视口均保留固定 `1920×1080` 逻辑世界、完整 HUD 与安全区。不得因 Web 视口另改碰撞、射程、Boss 预警或清场条件。
5. 首次在线完整加载后，静态缓存可支持断网重新打开；缓存未命中时必须回到加载失败/重试状态。新版本缓存到达时不得在进行中的对局中热刷新，下一次刷新页面后生效。

## 3. 双端版本与发布规则

### 3.1 单一发行身份

每次候选发布固定一个 `releaseVersion`（来自 `pubspec.yaml` 的 `x.y.z+n`）、一个 Git commit 与一个 `contentVersion`。macOS `.app` 与 Web `build/web/` 必须由这三项完全相同的输入构建。构建系统生成但不由游戏运行时消费的 `release-manifest.json` 必须包含：

```text
releaseVersion, contentVersion, gitCommit, buildUtc,
macosArtifactSha256, webArchiveSha256, webBaseHref,
flutterVersion, wasmEnabled
```

构建、QA、部署均不得手写或分别填写版本号；任一字段不一致即拒绝进入发布候选。

### 3.2 双端发布原子性

1. macOS 产物为签名后的 `.app`（分发渠道要求时再 notarize）；Web 产物为完整、不可拆分的 `build/web/` 静态目录压缩包。
2. 两端先上传为不可公开的同一 release candidate，完成共同验收后才同时切换为公开下载/站点版本。
3. 任一端构建、素材 hash、核心回归、平台验收或发布签名失败时，整个 release train 退回候选态；不得让另一个端使用同一 `releaseVersion` 先发布。
4. Web 仅部署静态文件，不需要登录、后端 API、数据库或远程配置。部署路径必须显式传入 `--base-href`；根路径发布用 `/`，子目录发布必须形如 `/warship/` 并以 `/` 结束。

## 4. Web 素材与托管要求

- 运行时只读取既有 `assets/config/v2/`、`assets/images/v2/`、`assets/audio/v2/`；根目录 `素材/v2.1/` 仍是交付源，禁止浏览器直接读取。
- 保留 PWA manifest、横屏偏好、图标与深色加载页。首屏不得引用外站字体、CDN 音频、第三方统计或未在素材清单登记的网络资源。
- HTTPS 是生产 Web 的硬要求；服务器须正确提供 `.wasm` 为 `application/wasm`。`index.html`、`flutter_bootstrap.js`、`flutter_service_worker.js`、`version.json` 使用不超过 5 分钟的可更新缓存策略；带内容 hash 的 `assets/`、CanvasKit/WASM 可使用长缓存。禁止把所有文件设为不可更新的永久缓存。
- 静态托管必须返回真实文件；本产品没有浏览器 URL 路由，禁止以 SPA fallback 把缺失的 `.wasm`、资源或 manifest 错误返回 `index.html`。

## 5. 产品验收与发布判定

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| WEB-P-01 | Web 首次打开 / 资源错误 | 正常首帧进入；网络错误或超时显示重试；不虚构下载百分比 |
| WEB-P-02 | 音频手势 | 手势前可无声且不阻断；手势后设置开启时 BGM/SFX 可听；拒绝时对局继续 |
| WEB-P-03 | 隐藏 / 恢复 | hidden 自动暂停；恢复不自动开战；时间、伤害、随机序列不在后台推进 |
| WEB-P-04 | 三种宽高比与最小窗口 | 4:3、16:9、21:9 无裁切；低于最小窗口不开始对局 |
| WEB-P-05 | 缓存/断网/更新 | 完整加载后可离线重开；首次离线显示重试；更新不热刷新正在进行的对局 |
| DUAL-P-01 | 同一发布候选 | 两端 `releaseVersion`、commit、contentVersion、素材 hash 一致；任一端未验收则不公开 |

产品验收不能以“Web 构建成功”代替真实浏览器体验，也不能以 macOS 验收代替 Web 验收。
